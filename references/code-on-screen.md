# 代码与图表上屏规范（全训练营通用 · 强制）

> **适用范围（2026-10-07 起由「读书训练营」扩至全部 9 大训练营）**：本规范**对架构师 / 大数据 / AI / 产品经理 / 前端 / 测试 / 管理 / 软技能 / 读书 九类训练营一律强制生效**，不再是读书营专属。凡内容涉及代码 / API / 配置 / 命令 / 公式 / 数据表 / 架构流程，**无论来自原书、官方文档、项目资产还是本机实跑**，一律按本规范上屏。
>
> 落地背景（2026-10-06，读书营首现）：Vue.js 设计与实现三部（50+54+46 = 150 页）成片**全程纯文字 + 字幕**，一个代码页都没有——口播在讲 `Proxy` 依赖收集、Diff 双端比较、模板编译，屏幕上只有字幕。根因不是执行时忘了，而是**技能规则从未要求「代码必须上屏」**，且素材获取环节只要求把书中图示「整理成文字描述」，图片文件从未被提取。本规范补齐这两处缺口。
>
> 2026-10-07 作者进一步明确：**读书营以外的其他训练营同样要按需把代码示例、图表、架构图、流程图放进视频，不许纯文字口述**。故本规范解除读书营限定，并同步解绑「出处标注必须写原书 P.N」这一读书营特有格式（见 §1.2 标注行）。

---

## 0. 四条总纲（优先级最高）

1. **凡口播涉及代码 / API / 配置 / 命令 / 公式 / 数据表 / 架构 / 流程，画面必须出现对应的真实视觉资产**，不允许「只念不显」。判断标准很简单：**如果观众关掉声音、只凭画面能不能跟上讲解？**跟不上就是缺视觉资产。
2. **纯文字页连续不得超过 3 页**。一条视频里「标题 + 要点 + 字幕」的纯文字页占比不得超过 40%。超了就必须补代码页 / 图示页 / 图表页 / 数据页。
3. **正确性优先**：代码必须来自**可溯源的权威来源**（`build/book_source.md` 记录的书中原文 / 官方文档原文 / 本机实跑输出），**不得凭记忆手写代码**；来源里没有的代码不硬造（见 SKILL.md「内容必须忠于权威来源」红线）。
4. **无出处不落画（2026-10-07 起）**：任何代码块 / 图示 / 图表上屏都要带**来源标注**。读书营写 `原书 P.<页> · <书名> §<章节>`；其余训练营写 `来源：官方文档 <URL> · <章节>` 或 `本机实跑 <环境/版本>`。**没有来源标注 = 未完成，不得上屏。**

## 1. 代码上屏（强制）

### 1.1 触发条件（命中任一即必须上屏）

| 口播出现 | 画面必须出现 |
|---|---|
| 具体函数 / 类 / 方法名 | 函数签名 + 关键实现代码块 |
| 伪代码 / 流程步骤 | 等宽字体代码块（可只列骨架） |
| API 调用、参数、返回值 | 调用示例代码块 |
| 命令行操作 | 终端样式代码块（含提示符与输出） |
| 配置项 / 环境变量 | 配置文件片段（`package.json` / `tsconfig.json` 等） |
| 数据结构 / 算法 | 输入输出示例 + 核心逻辑 |
| 对比两个写法 | 两栏代码并排，高亮差异行 |

### 1.2 代码块排版规范

```
┌─────────────────────────────────────┐
│  src/reactivity/effect.ts        ← 文件路径（小字，等宽，弱化）
├─────────────────────────────────────┤
│  1  export function effect(fn) {     │  ← 行号（可选但推荐）
│  2    const trackings = new Set()    │
│  3    activeEffect = {              │
│  4      fn,                          │
│  5      deps: new Set(),             │
│  6      trackings                    │
│  7    }                               │
│  8    cleanup()   // ← 关键行，主题色高亮
│  9    try { fn() } finally {         │
│ 10      activeEffect = prevEffect    │
│ 11      prevEffect.deps.forEach(...) │
│ 12    }                               │
│ 13  }                                 │
└─────────────────────────────────────┘
      原书 P.87 · Vue.js 设计与实现 §3.4   ← 出处标注（小字，页脚上方）
```

**硬约束**：

| 项 | 要求 |
|---|---|
| 位置 | 主体代码块收在画面**顶部 85% 安全区内**，下方留字幕带；出处标注紧贴代码块下沿、**不得落入字幕带** |
| 字号 | 等宽字体**正文 ≥ 26px**（1920×1080 基准）。行数超限时**截断而非缩字** |
| 行数 | **单屏 10~25 行**。超了必须截取关键片段（`// ... 省略中间 ...` 显式标注省略） |
| 配色 | 深色代码块（`#1E1E2E` / `#282A36` 系）或浅色代码块（`#F6F8FA` + 深字），**同一视频内只用一种**；用训练营主题色做**关键字高亮 / 行号强调 / 边框**，不用作代码块底色 |
| 语法高亮 | 至少区分 关键字 / 字符串 / 注释 / 函数名 四类；**中文注释可保留**（书里的解释性注释是有价值的信息） |
| 标注 | 代码块**必须带出处标注**（小字、弱化、置于代码块下方），格式按来源分三种：①读书营 → `原书 P.<页> · <书名> §<章节>`；②其他训练营引用官方资料 → `来源：官方文档 <URL> · <章节>`；③本机实跑 → `本机实跑 <环境/版本/日期>`。**无标注不上屏** |
| 版权 | 代码属**事实性内容**，可直接上屏，但**必须标注出处**；不得整段照搬书中超过 30 行的连续代码（防侵权），超长时截取片段。非读书营的代码/配置同样不得整段照搬官方文档超 30 行连续内容 |

### 1.3 关键行的视觉强调

讲解的核心那 1~2 行必须**高亮**（背景色块 / 左侧竖线 / 箭头标注），让观众视线能落到关键处。例如讲「为什么要用 `try...finally` 恢复 `activeEffect`」，就把第 10 行高亮 + 一条引线标注「这里出栈，栈顶恢复成外层 effect」。

### 1.4 与字幕带的关系

代码块底部与字幕带之间**至少留 24px 空隙**。字幕**不允许**压在代码块上——代码块是本视频的核心视觉资产，被字幕盖住等于该页白做。合成后抽帧校验（沿用 SKILL.md 固定规范第 15 条）。

## 2. 第三方图表的处理（重绘为主，禁直接搬）

> 本章原为「书中图表」，2026-10-07 起扩为**一切第三方图表**（原书图 / 官方文档配图 / 社区博客配图 / 素材站图）。读书营额外禁止「截书页像素」，非读书营额外禁止「直接搬官方文档图片」而不标来源——**去侵权红线对所有训练营一致生效**。

### 2.1 来源优先级链

```
① 原书图表 → 重绘为同构图示意图（标「据原书 P.N 重绘」）   ← 读书营默认路径
①' 官方文档 / 官方仓库 / 官方博客配图（可注明出处直接引用）← 其他训练营默认路径
② 官方渠道原图（作者官网 / 官方文档 / 官方仓库配图）        ← 优于重绘
③ 授权素材库（明确可商用）                                ← 需留授权凭证
④ HTML/SVG 自绘原创示意图（忠于概念不复制像素）             ← 兜底
```

**❌ 严禁**：直接截取书内图表像素上屏、扫描书页当插图、把 PDF 页导出为图片使用；同样**严禁把官方文档/博客的配图直接下载搬进画面而不标注来源**。**这是去侵权红线**（与 SKILL.md Step 2 §3.1 联动），一旦命中即视为不合格，须返工。

### 2.2 重绘的「同构」要求

重绘不是随便画个示意图，须满足：

- **结构一致**：节点、层级、连线关系与原图对应（不增删关键元素）
- **标注一致**：原图中的文字标签照搬（文字不受著作权保护），但排版可优化
- **标注出处**：图示角落标 `据原书 P.<页> 重绘`
- **风格统一**：与全片其他图示同一套配色与线宽

### 2.3 什么该重绘上屏

| 内容类型 | 处理 |
|---|---|
| 架构图 / 流程图 / 时序图 | **优先重绘上屏**（分层架构、调用链路这类整章流程图最典型） |
| 对比表格 | 转成幻灯片的对比表版式（`visual-design.md` §2.1），保留原始数值 |
| 数据图表（性能对比 / 基准测试） | 转成柱状图 / 折线图（§2.2 / §2.3），**必须保留原始数值并标注来源** |
| 状态机 / 生命周期图 | 重绘为状态转移图 |
| 纯装饰性插图 | 不上屏 |

## 2A. 非读书营的素材获取（2026-10-07 新增 · 与 §3 并列的取材路径）

§3 讲的是**读书营**从原书提取图表/代码的路径。其他训练营没有原书，走下面这条：

### 2A.1 取材来源（按可信度降序）

| 来源 | 适用 | 怎么取 |
|---|---|---|
| **本机实跑** | 命令、SQL、代码、配置、性能数据 | 本机有环境就直接跑，**终端块三段齐全（提示符+命令+真实输出）**；跑不了退回下方来源 |

## 3. 素材获取环节的补齐（这是根因所在）

### 3.1 提取原书图片文件（新增必做步骤）

`build/book_source.md` 的既有职责是**文字化整理**。现在**新增并列产物**：凡书中含代码清单 / 图表 / 数据表的章节，须**同时提取为独立文件**：

```
build/
├── book_source.md          # 文字化整理（既有）
├── book_figs/              # 新增 · 原书图表图片（去水印后仅作重绘参考，不直接上屏）
│   ├── ch03_p87_fig1.png
│   └── manifest.json       # 每图记录：原书页码 / 章节 / 类型 / 简述
└── code_snippets/          # 新增 · 代码清单文本（可直接上屏的素材）
    ├── ch03_p87_effect.ts  # 原样摘录 + 顶部注释写明出处
    └── manifest.json       # 每段记录：原书页码 / 章节 / 行数 / 可上屏判断
```

**PDF 路径**：`pdfimages` 提取嵌入图 / PyMuPDF 渲染指定页为高分辨率 PNG（≥200 DPI）后裁切；**EPUB 路径**：解包 spine 中的图片资源；**实体书扫描件**：按页裁切。三条路径都拿不到时，在 `book_figs/manifest.json` 记 `coverage: "无图"` 并在 `book_source.md` 头部注明，**不阻塞生产**（改走 §2.1 ③④兜底）。

### 3.2 素材台账（写进 `book_source.md`）

每条代码 / 图表素材在 `book_source.md` 里带一行台账，供 Step 2 排版时直接取用：

```

| S-07 | 代码 | Vue.js设计与实现 | P.87 §3.4 effect() | code_snippets/ch03_p87_effect.ts | 上屏（截取 13 行，关键行高亮） |

| F-05 | 对比表 | Vue.js设计与实现 | P.95 表 5-1 | — | 转对比表版式，保留原数值 |
```

`画面处置` 列取值：`上屏` / `重绘上屏` / `转图表版式` / `不上屏（装饰）`。

### 3.3 提取时必须做的清洗

- 去掉书页页眉 / 页脚 / 页码（它们不是内容）

- 代码块去掉书里的**行号残留**与**跨页断行**，但**保留中文注释**

## 4. Step 2 排版的强制判据（全部 9 大训练营通用）

排完版、导帧前逐条过，任一不过即返工：

- [ ] 本片是否存在**连续 ≥3 页**的纯文字页？有则必须插入代码页 / 图示页 / 图表页打断
- [ ] 口播提到**每个**函数名 / API / 命令 / 配置项，是否都有对应代码块上屏？
- [ ] 每个代码块是否 **≤ 25 行**、字号 **≥ 26px**、收在顶部 85% 内？
- [ ] 每个代码块是否带**出处标注**（读书营＝原书页码+章节／其他营＝官方文档 URL 或本机实跑环境）？
- [ ] 讲解的**关键行**是否高亮？
- [ ] 每张第三方图示是否**重绘或已标来源**（非读书营：官方文档/博客配图直接搬也须标 URL；读书营：一律重绘）？
- [ ] 数据图表是否**保留原始数值**并标来源？
- [ ] 纯文字页占比是否 **≤ 40%**（实战内容密集的片子收紧到 30%）？
- [ ] 字幕带内是否**无代码块 / 图示内容**侵入？
- [ ] 关键行是否**未被字幕遮挡**（合成后抽帧核验）？

## 5. 反面案例（已发生的错误，勿重犯）

| ❌ 错误 | 后果 | ✅ 正确 |
|---|---|---|
| 通讲 `Proxy` 依赖收集，屏幕只有字幕 | 观众看不到 `targetMap` / `deps` 的实际结构，纯听不直观 | 上屏 `reactive.ts` 关键 15 行，高亮 `track(target)` |
| 讲模板编译五阶段，屏幕是三个方框加箭头 | 图是 AI 画的简化框，丢了原书的状态机细节 | 重绘原书 P.156 编译流程图，标「据原书 P.156 重绘」 |
| 把书中性能对比表的数据写成口播数字 | 数字只在声音里，画面无对比 | 转柱状图 + 保留原书数值 + 标来源 |
| 讲 `Diff` 双端比较，只画了首尾两个游标示意 | 遗漏中间区间搜索过程，讲不清 | 上屏原书 Diff 实现代码 + 高亮四个端点指针 |
| 靠人工写 `add_source_examples.py` 往口播稿塞「书中例子」 | 例子变成**口播文字**（"用3个key为A、B、C练习重排"），画面依然纯文字 | 按本规范让**代码本身**上屏，而非用文字描述代码 |

**最后一条是本次的核心教训**：上一轮补救时把「书中例子」塞进了**口播稿**，而不是让**代码出现在画面**——方向错了，等于用文字描述代码。正确做法是代码上屏，口播只负责讲解代码在做什么。

## 6. 配套能力

- **语法高亮**：渲染时用 highlight.js / Prism.js / shiki 对代码块着色（CSS 类或内联样式均可），产物为静态 HTML 供 `render_frames.py` 截帧
- **原书 PDF 图提取**：`pdfimages -png`（poppler-utils）或 PyMuPDF `page.get_pixmap(dpi=200)`
- **图表重绘**：走`references/diagram-generation.md` 的架构图生成技能，或 HTML/SVG 自绘（§2.1 ④）
- **视觉资产合规**：入画前去侵权检查沿用 `visual-design.md` §4
