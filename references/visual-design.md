# 专业视觉设计系统（Professional Visual Design System）

> 本文档是「让画面更专业、更动态、信息密度更高」的规范来源。供 Step 2（生成 HTML 幻灯片）、Step 6（封面 + 合成）使用。
>
> 目的：把视频从「纯文字 + 单色块」提升为「**设计版式 + 数据图表 + 图示 + 适度动效**」的专业课件级画面，同时**不破坏**既有硬约束（左上角水印安全区 / 底部字幕带 / 训练营主题色 / 去侵权 / 画面无训练营标识期号）。

---

## 0. 三条总纲（优先级最高，任何版面都先过这三条）

1. **专业 ≠ 炫技**：动画与装饰是为了**讲清逻辑**，不是为动而动。能静态讲清的不用动画；动画时间被占用时宁可不加，不加到影响观看节奏。
2. **信息分层**：一屏只突出「1 个结论」+「≤3 个支撑点」+「1 个视觉焦点」。做减法 > 加花哨。多信息放不进一屏就拆两屏，不堆一屏。
3. **所有视觉服务于「字幕/声音/内容/画面」四方同频**：任何版式、图表、动画都不得侵入左上角水印安全区（x 0~25% × y 0~15%）与底部字幕带（y 88%~95%）。排版在前、水印与字幕最后落位。

## 1. 版式系统（Layout System）

每页幻灯片从下面**固定版式**里选，禁止自由堆叠文字。按内容类型匹配：

### 1.1 卡片式（Card）—— 要点并列 / 多方案对比
- 主体是一组**等宽卡片**（2~5 张），每张：小图标 + 短标题 + 一行要点。
- 卡片网格须**对齐**：同行卡片同高、同间距，边缘对齐；卡片间距固定（gap 统一 24~40px）。
- 颜色：当前讲到的卡片用训练营高亮色**描边 + 微亮底**，未讲到的用中性深色底（制造「讲到哪」的推进感）。
- 不要：卡片内塞长段落。

### 1.2 双栏 / 三栏（Split）—— 对比 / 因果 / 演进
- 左旧 vs 右新、上因下果、左问题右方案。栏间留一条**纵向分隔**（细线或虚箭头）。
- 栏顶各放一个**栏标题**，标题同一行对齐。
- 对比内容强推用**表格**而非两段文字（见 §2.1）。

### 1.3 主视觉 + 说明（Hero）—— 封面页 / 单结论页
- 大结论（≤20 字，白字大号）居中偏上；下方一句副信息。
- 背景用该训练营同色系**渐变 + 微弱几何装饰**（放射线 / 圆环 / 网格点阵，透明度 ≤15%，避免抢文字）。
- 数字型结论用「**大数字**」呈现（见 §2.4）。

### 1.4 图示页（Diagram）—— 架构 / 流程
- 一张图讲清一个结构，图占版面 55%~75%，四周留白。
- 图内节点用**圆角矩形 + 该训练营主色描边**，连线用直线/折线，箭头明确方向。
- 节点文字 ≤8 字；超长拆子节点。图例放图下方小字。
- **图示底部必须收在字幕带以上**（见 video-production.md §4 / SKILL.md 固定规范第 15 条）。

### 1.5 数字聚焦页（Stat）—— 单点强冲击
- 全屏只有一个**超大数字/结论**（占高 30%~50%），下方一行小字解释。
- 数字用渐变或高亮色填充，白色描边保证对比度。

## 2. 图表模板（Chart Templates）

「有数据、有对比、有流程的内容，**必须用图/表/图示呈现，禁止纯文字平铺**。」数据页优先用下列内联 SVG 图表（HTML 直接画，稳定、无版权、可精确配色）。matplotlib/PIL 为辅，不默认。

### 2.1 对比表（Comparison Table）
适用：两/多方案特性对比、版本差异、语言/框架对比。
- 表头一行（方案名），首列是**对比维度**，单元格短词/勾叉/数值。
- 「优」用高亮色、「劣」用中性灰、可加 `✓`/`✗` 或 `▲▼`。
- 行高留白充足（≥56px），避免密集拥挤；**行数 ≤8，列数 ≤4**，超出拆多张。
- 强调某一列/某一行时，对该行/列加高亮底 + 描边。

### 2.2 柱状图 / 条形图（Bar）
适用：数值对比（性能、耗时、成本）。
- 统一基线、等宽柱、柱间距 ≥ 柱宽的 1/2。
- 数据最高 / 与主题相关的柱用高亮色，其余用中性低饱和色（弱化衬托）。
- 柱顶直接标数值，避免靠 y 轴刻度读值。
- 横向条形适合长分类名；纵向柱适合少分类（≤6）。

### 2.3 折线 / 趋势图（Line / Area）
适用：时间趋势、规模增长、延迟随 N 变化。
- ≤3 条线，主线用高亮色加粗，对比线用中性色虚线。
- x/y 轴给单位；关键拐点 / 结论点画**数据点标记 + 文字标注**。
- 趋势结论用**面积渐变**增强（同色系透明度渐变），或加一条目标基准线（虚线）。

### 2.4 环形图 / 占比（Donut）
适用：组成占比（成本结构、流量来源、市场份额）。
- ≤6 段，段间用底色细缝分隔；最大 / 要强调的一段用高亮色，其余低饱和。
- 圆心放总数值或一句话结论。
- 段名放图例（图外），不直接压饼上（饼太小）。

### 2.5 大数字 / KPI（Stat Number）
适用：单个量级冲击（`74秒 → 2.3秒`、`成本直降90%`）。
- 数字用该训练营高亮色渐变，尺寸 ≥ 画面宽 40%，加轻微白描边。
- 前后对比：旧值灰色 + 删除线 → 新值高亮大号（配一个箭头动画可选）。
- 单位（秒/%/倍）随数字同级显示，勿小到看不清。

### 2.6 架构 / 流程图（Diagram）
- 见 §1.4。提供基础**图元**：进程/服务（圆角矩形）、数据库（圆柱形）、队列/流（箭头带）、外部依赖（菱形/云）。
- 层与层之间用分区底色（同色系不同透明度）分隔，标「层名」于侧边小字。
- 数据流方向统一（左→右 或 上→下），不要来回绕。

### 2.7 时间线（Timeline）
适用：演进历程、里程碑、步骤阶段。
- 一条主轴（水平或垂直），节点圆点 + 短标签 + 一行说明。
- 当前所处节点用高亮色放大，历史节点灰、未来节点虚。

## 3. 动效 / 动画指引（Motion Guide）

目标是消除「静态感」让画面专业。**两层动效**：①页面内部**揭示动效**（HTML/CSS 层）；②整片**镜头运动**（合成层 ffmpeg）。二者叠加即可，不需要更复杂。

> 关键认知：**「动态感」的主来源是整片镜头运动（zoompan 缓慢推拉），不是每页堆动画**。正文页即使静态版式，套上轻微 Ken Burns 推拉后整支视频就"活"了。HTML 内揭示动效只用于「关键页的结论强调」，克制使用。

### 3.1 镜头运动层（合成层 · ffmpeg · 推荐必做）
- 用 `scripts/compose_motion.py` 对静态帧目录做 **Ken Burns**（缓慢推/拉/平移）+ **交叉淡入过渡（xfade 0.4~0.6s）**，替换原先的硬切 + 帧拼接。
- 节奏：正文页推拉量小（scale 1.00→1.06 的缓慢放大或左右平移 1~2%），避免观感眩晕；关键页可稍大。
- 优点：不改 HTML、不重渲帧、不动时间轴——只换「合成」环节，四方同频字幕/时长不受影响（帧停留时长仍取 `segments_durations.json`）。
- 封面段可做轻微 zoom-in（1.0→1.04）提升开场呼吸感。

### 3.2 页面揭示动效（HTML/CSS 层 · 克制）
仅用于：结论数字弹出、方案高亮推进、箭头出现引导视线。不用于每页每元素。
- **禁用**整体页间转场动画（交给 §3.1 的 xfade）；HTML 内不做「页面淡入淡出」。
- 允许的局部动效：
  - 数字**滚数/弹入**（结论数字从 0 滚到终值，600ms 缓出）。
  - 要点**逐条渐入**（opacity 0→1 + 上移 8px，stagger 150ms/条）——但**必须与配音讲到的节奏一致**（若配音是一次性讲完，就用一次性显示，不要逐条卡在配音前）。
  - 高亮卡**推进标记**（讲到的卡描边 + 上浮 3px）。
  - 简单**箭头/流程线**描边绘制。
- 实现：CSS `@keyframes` + `animation-fill-mode: forwards` + 页面自带 JS（滚动/翻页触发）。由于是导出 PNG（静态），**这些局部动效主要用于"直接演示/录屏回放"或 Remotion 路径**；走静态帧导出时，关键页把"动效终点态"作为该页静态画面即可（保证静态帧也完整表达），不依赖动效才能看懂。

### 3.3 动效纪律
- 单页动效元素 ≤2 处；总动画时长占比 ≤ 画面停留的 20%。
- 动画不得遮挡水印安全区 / 字幕带（缩放、位移动画须限定在内容区）。
- 动画结束时内容必须完全静止可读（`forwards`），不在运动中间结束一页。

### 3.4 模板内置动画类（与 `templates/slide-template.html` 对齐 · Step 2 套模板时直接用）

| 类 | 效果 | 典型用途 | 时长 |
|----|------|----------|------|
| `.anim-fade-up` | opacity 0→1 + translateY 26→0 渐入；要点逐条加 `.d1`/`.d2`/`.d3`/`.d4` 做 stagger 150ms | 卡片要点、对照列表的逐条揭示 | 0.6s |
| `.anim-pop` | scale 0.82→1.04→1 + opacity 弹入（缓动 cubic-bezier(.2,.7,.3,1.2)） | 数字聚焦页大数字、关键结论 | 0.55s |
| `.anim-highlight` | 描边色从 `--line` 过渡到 `--hilite` | 当前讲到的卡推进高亮 | 0.5s |
| `.anim-draw` | SVG `stroke-dashoffset` 1200→0 描边绘制 | 架构/流程图的连接线、分支箭头 | 1.2s |
| `.anim-fill` | `scaleY` 0→1 从底部填充 | 柱状图柱体、进度条 | 0.9s |
| `.anim-pulse` | 数字 glow 脉冲（drop-shadow 循环） | 强调数字持续吸睛 | 2.2s 循环 |

数字滚数（0 → 终值，800~1000ms 缓出）由模板内 `.js-count` + JS 在页面加载后用 `requestAnimationFrame` 实现，给元素加 `data-count="2.3"` 即可；静态帧导出时终态即终值（不影响可读），CSS 动画若需真正进入成片走 `scripts/render_animated.js` 逐帧截屏（§7）。

纪律：**单页 ≤2 处动效、动画类写在内容元素上而非容器上**（避免整页一起淡入），动画区间不得侵入左上角水印安全区（x 0~25% × y 0~15%）与底部字幕带（y 88%~95%）。

## 4. 视觉资产与来源

- **图标（语义准确 + 入画 · 强制 · SKILL.md 固定规范第 26 条）**：
  - **理解对（语义准确）**：图标语义与概念**严格对应**——讲「数据库」用数据库/圆柱图标、「安全」用锁、「时钟/定时」用时钟、「网络」用地球/节点、「存储」用磁盘……**不望文生义、不张冠李戴**；讲具体产品/技术用其**官方 Logo**（MySQL 海豚 / Docker 鲸鱼 / Kubernetes 舵轮 / Redis / Doris 等），不混用、不错用品牌图标；**拿不准的图标宁可自绘抽象图形或省略，不硬塞一个错的**。
  - **放进画面（入画）**：内容讲到图标 / Logo / 图元时，画面里**必须有对应图标呈现**（不是只有文字空讲），图标与文字配套、大小配色正确、收在顶部 85% 安全区内（避开左上角水印区与底部字幕带）。
  - **风格统一**：同一视频内统一线性或面性一套（不混搭），配色取训练营高亮色 / 中性白灰。
  - **来源合规**：优先项目资产 `项目 / 资产 / We-Media`（图标库），无则用开源线性图标（Lucide / Feather）自绘；专有 Logo 走官方渠道；**禁用带第三方水印/来源不明的图标**（去侵权见 SKILL.md Step 2 §3.1）。
- 架构 / 流程 / 示意图：**优先官方原图**（官网 / 官方文档 / 官方博客，见 SKILL.md Step 1 / Step 2 §3）；需重绘时用 HTML/SVG 自绘原创示意图，忠于原图概念但不复制像素（读书训练营见「核心内容入画」规则）。
- 所有图/表/图示入画前做**去侵权检查**（第三方水印 / 版权角标 / 无关 Logo / 网址域名，处理优先级见 SKILL.md Step 2 §3.1）。

## 5. DO / DON'T 速查

| ✅ DO | ❌ DON'T |
|------|---------|
| 每页 = 一个版式（卡片/双栏/主视觉/图示/数字聚焦） | 每页随机堆文字+色块，无固定网格 |
| 有数据/对比/流程 → 用图、表、图示（§2） | 数据只写成一段话 / 一句话平铺 |
| 用训练营高亮色做强调、中性色做衬托 | 满屏同色块或杂色乱入 |
| 版式内容收在画面顶 85%、四周留白 | 内容延伸到字幕带 / 顶到水印区 |
| 正文套轻微 Ken Burns 镜头运动（§3.1） | 整片一帧一帧硬切、画面全程静止 |
| 关键结论页加 1~2 处克制揭示动效（§3.2） | 每页每元素都动、动画抢讲解 |
| 关键数据用大数字 + 图表呈现（§2.4/2.5） | 数字只出现在口播里、画面无对应视觉 |
| 图元统一风格、对齐网格 | 图标风格混搭、节点乱放不齐 |
| 复杂信息拆多屏，一屏一个焦点 | 一屏塞满塞不下 |

## 6. 自检（合成前逐页过）

- [ ] 每页套用了 5 大版式之一，无自由堆叠页。
- [ ] 有数据/对比/流程的页已用图/表/图示（不是纯文字）。
- [ ] 图表配色 = 训练营高亮色 + 中性色，无杂色。
- [ ] 卡片/图元对齐、间距统一；无重叠、无溢出截断。
- [ ] 页面文字/图表主体收在顶部 85% 内，未侵入左上角水印区与底部字幕带。
- [ ] 静态帧导出状态下，即使无动画，每页也完整可读（结论/数据在画面里）。
- [ ] 合成采用 Ken Burns 镜头运动 + 交叉淡入（或明确该片不用运动的原因）。
- [ ] 无第三方水印/版权角标/无关 Logo/网址残留。

## 7. 动画帧导出（CSS 动画真正进入成片 · `scripts/render_animated.js`）

**为什么需要**：默认管线「HTML → 每页 1 张静态 PNG → `compose_motion.py`」会把页面内 CSS 动画全部丢失（静态帧只有动画终点态）——模板里 `.anim-pop` / `.anim-draw` / `.anim-fade-up` / `.anim-fill` / 数字滚数这些动效，静态导出后只剩"结束态"画面。本节提供让这些动画**真正进入成片**的可选路径。

### 7.1 工具与原理
- **`scripts/render_animated.js`**（node ≥22 内置 WebSocket/fetch + Chrome CDP + ffmpeg）
- 原理：headless Chrome 加载每页 HTML，对该页停留时长内按 fps 做**真实时间推进的逐帧截屏**，CSS 动画在真实时间里自然推进 → 把动画全程捕获为 PNG 序列 → ffmpeg 按 fps 拼成 body 视频
- 关键参数：CDP `Page.navigate` 加载 `?page=N` → 等首帧渲染 → 循环 `Page.captureScreenshot` + `setInterval(1000/fps)`

### 7.2 与 Ken Burns 的关系
**互斥**：动画帧导出时帧序列已含动画的动态感，不再叠加 Ken Burns；非动画页（如纯卡片页）继续走 `compose_motion.py`。默认仍走静态帧 + Ken Burns；仅当关键页（数字聚焦 / 流程绘制 / 卡片推进）需要 CSS 动画进视频时启用本路径。

### 7.3 用法
```bash
node scripts/render_animated.js <PPT.html> <segments_durations.json> <out_body.mp4> \
    [--fps 30] [--only-page N] [--chrome /path/to/Chrome] [--port 9333]
```
- `--fps 30`：CSS 揭示动画 15~30 fps 足够（默认 30）
- `--only-page N`：调试用，只导一页
- 依赖：Chrome（mac 默认 `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`，需 `--no-sandbox`）、node ≥22（内置 WebSocket）、ffmpeg（帧序列拼接）

### 7.4 坑与边界（已踩/验证）
- **Chrome 在沙箱环境需 `--no-sandbox`**：macOS sandbox 启动失败（`sandbox initialization failed: Operation not permitted`）会让 GPU/network service 崩溃、DevTools 端口不上线；脚本已加 `--no-sandbox --disable-gpu --disable-dev-shm-usage --disable-software-rasterizer`。
- **Chrome 新版 `/json/new` 需 PUT**：创建 target 用 `PUT /json/new?about:blank`（GET 405），再 `Page.navigate` 到目标 URL；不要用 GET。
- **音频/字幕与动画帧对齐**：`segments_durations.json` 仍是画面停留与字幕时间的**唯一来源**（每页时长 = 该页配音真实时长），动画帧导出只换合成方式、不改时间轴 → 四方同频不受影响。
- **每页加载后等 ~350ms 再开始截图**：让首帧渲染与 CSS 动画启动；数字滚数等 `requestAnimationFrame` 类动画需要这一延迟。
- **动画结束后静止帧会重复**：CSS 动画时长（如 0.9s）< 该页停留时长（如 6s）时，动画结束后帧序列是静止画面占满剩余时长——这是预期的（与配音节奏一致）。

### 7.5 何时启用（决策原则）
- **关键页有数字滚入 / 流程绘制 / 卡片推进高亮**：启用本脚本替换该页（必要时按页分段导出再 concat）
- **整片都是静态版式**：不启用，沿用静态帧 + `compose_motion.py`
- **作者明确要求"CSS 动画要进视频"**：全片用 `render_animated.js`（Ken Burns 与动画帧二选一）

### 7.6 与 §3 动效的关系
§3 的动效指引（克制、单页 ≤2 处、不挡水印/字幕带）是**动画设计纪律**；§7 是**动画导出落地**。两条并列：先按 §3 设计动效，按 §7 决定导出方式。
