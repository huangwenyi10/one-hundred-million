# 实战类内容视觉化规范（读书训练营 · 强制）

> 落地背景（2026-10-06）：作者指出「如果书籍是实战类的，或者内容有实战类的，要按需把实战内容或者图表、代码、演示表现出来，让读者能够清楚理解」。此规范把「上屏」从**只针对代码**扩展到**全部实战载体**——代码只是其中一种，架构图、SQL、执行计划、终端操作、公式推导、对比实验、完整案例同样必须上屏。

---

## 0. 与 `code-on-screen.md` 的关系

| 文档 | 覆盖范围 |
|---|---|
| `code-on-screen.md` | **代码 / 命令 / 配置 / API** 的排版硬约束（字号、行数、出处标注、版权红线） |
| **本文档** | **实战类内容的识别与强制视觉化**——判断「这段是不是实战」、该用哪种视觉载体、以及载体不够时怎么办 |

代码上屏的排版细节仍以 `code-on-screen.md` 为准，本文不重复。**两文档同属交付硬门槛，任一不过即返工。**

## 1. 实战类内容的识别（强制判定）

### 1.1 什么算「实战类内容」

命中任一即为实战类，**必须按§2 配视觉载体**：

| 类别 | 特征 | 典型书 |
|---|---|---|
| **代码实现类** | 给出函数 / 类 / 模块的实现、调用、改造 | 《Vue.js 设计与实现》《算法导论》 |
| **命令操��类** | 给出可执行的 shell / SQL / 命令行 | 《MySQL必知必会》《鸟哥的Linux》 |
| **系统设计类** | 给出架构方案、组件划分、部署拓扑、容量估算 | 《架构整洁之道》《DDD》 |
| **数据处理类** | 给出 SQL、索引、查询计划、执行流程 | 《数据仓库实战》 |
| **配置调优类** | 给出配置文件、参数、参数间权衡 | 《高性能MySQL》《Redis设计与实现》 |
| **算法推演类** | 给出步骤、递推、状态转移、公式 | 《算法图解》 |
| **案例复盘类** | 给出真实案例的来龙去脉、数据、结论 | 《阿里测试之道》《SRE》 |
| **对比选型类** | 给出方案 A/B 的数据与取舍依据 | 《架构师修炼手册》 |
| **公式定理类** | 给出公式、定理、推导过程 | 《深入理解计算机系统》 |
| **工具实操类** | 给出工具的操作流程、界面、配置 | 《成为AGI产品经理》 |

### 1.2 书籍整体是实战书时

若**整本书**属实战类（如《Vue.js设计与实现》《MySQL必知必会》），则：

- **默认整片都应有代码 / 图示 / 演示页**，不是「按需」而是「**逐段按需**」——每一段实战内容配一段对应视觉
- **纯文字页占比上限收紧到 30%**（比通用 40% 更严）
- **每一部至少 25% 的页面是代码页或图示页**

若**书中部分章节**是实战类，则只对该部分强制，其他章节按通用规范。

## 2. 实战视觉载体清单（按优先级选）

判断顺序：**从下往上选第一个可行的**。越靠上越能让读者「看懂并跟着做」。

| 优先级 | 载体 | 适用 | 画法 |
|---|---|---|---|
| **P0** | **可运行代码** | 函数 / 类 / 模块 / API / 配置 | 真代码 + 语法高亮 + 关键行高亮 + 出处（`code-on-screen.md` §1） |
| **P0** | **命令与输出** | 终端操作、SQL 执行 | 终端样式块，**提示符 + 命令 + 真实输出**三段齐全，输出高亮变化行 |
| **P0** | **SQL + 执行计划** | 数据库 / 数仓主题 | 左SQL 右执行计划或结果集，关键扫描行标注；**数据量级来自原书** |
| **P1** | **重绘架构图 / 流程图** | 系统设计、调用链、请求流程 | 重绘（**不截书页**），标「据原书 P.N 重绘」 |
| **P1** | **状态机 / 时序图** | 生命周期、状态转移 | 重绘，节点与箭头标注事件 |
| **P1** | **数据图表** | 性能对比、基准测试、容量 | 柱状 / 折线（`visual-design.md` §2.2/2.3），**保留原书数值 + 标来源** |
| **P1** | **对比表** | 方案选型、优缺点 | 对比表版式（`visual-design.md` §2.1），**保留原始数值与结论** |
| **P2** | **分步演示序列** | 操作系统、工具实操、界面操作 | 2~4 帧连续画面，**同一构图的渐变序列**，配「①→②→③」步骤标 |
| **P2** | **公式推导** | 算法复杂度、容量估算、定理 | 逐行推导，每步只高亮新增项；数学符号用等宽或数学字体 |
| **P2** | **实例数据推演** | 算法步骤、状态变化 | 输入 → 中间态 → 输出，**中间态逐个展示**，不是只给最终答案 |
| **P3** | **手写推演纸样式** | 算法、状态机的手工推导 | 浅色横线纸背景 + 手写感字体，营造「演算」现场感 |
| **❌** | **纯文字罗列** | —— | **一律不合格** |

### 2.1 「演示」的表现形式（作者明确提到）

实战内容里的**操作过程**不该只用一张静态图，而应体现**过程**。三种做法：

1. **分步序列帧**（推荐）：同一主体在2~4 个关键步骤的截图/重绘帧，连续呈现，帧间加箭头或步骤序号 `①②③`
2. **代码逐步高亮**：全屏代码，讲解到哪一行哪一行高亮 —— 静态图 + 合成时的Ken Burns 配合
3. **前后对比**：同一场景「改动前 / 改动后」并排，差异行高亮

**禁止**：把过程压成一张图然后用口播描述过程（等同于「用文字描述代码」的老毛病）。

## 3. 实战内容的强制判据

### 3.1 一句话判据

> **「读者看完这一屏，能不能照着做？」**
> 不能，就是缺载体。缺载体就要补，不是靠口播补。

### 3.2 逐段打标（Step 1 写稿阶段就要做）

口播稿写完后，**逐段标注该段属于哪类实战内容、应配什么载体**，写入 `build/visual_plan.md`：

```
| 段号 | 口播要点 | 实战类别 | 画面载体 | 素材来源 | 优先级 |
|---|---|---|---|---|---|
| 07 | effect() 用 try...finally 恢复栈顶 | 代码实现类 | 代码块 13 行，关键行高亮 | code_snippets/ch03_p87.ts | P0 |
| 12 | 双端 Diff 用 4 个游标推进 | 算法推演类 | 分步演示序列 4 帧 | 自绘（据原书 P.204） | P1 |
| 19 | MySQL 索引失效的 4 种情况 | 命令操作类 | 终端块 + EXPLAIN 输出 | 原书 P.88 | P0 |
| 25 | 服务端渲染比客户端多一次序列化 | 系统设计类 | 重绘流程图 | book_figs/ch06_p112.png 重绘 | P1 |
```

**这张表是排版的输入**，Step 2 排版时逐行对应；Step 6 交付时逐行验收。

### 3.3 实战内容占比下限（强制）

| 内容类型 | 实战视觉页下限 |
|---|---|
| 整本实战书 | **≥25% 页面**为代码页 / 图示页 / 演示页 |
| 含实战章节的混合书 | 实战章节内 **≥30%** |
| 纯理论书 | 纯文字页≤ 40%（通用口径） |

## 4. 素材来源与版权

### 4.1 优先级链

```
① 原书代码 / 命令 / SQL / 图表  →  提取为文本或重绘上屏（标出处）
② 官方文档原图（作者官网 / 官方仓库 / 官方文档配图）
③ 授权素材（明确可商用，留凭证）
④ 自行重绘（忠于概念不复制像素，标「据原书 P.N 重绘」）
⑤ 本机实跑生成真实输出（终端块 / 结果集）—— 最可信，优先
```

**第⑤条实战价值最高**：书中给的命令/SQL，**能在本机跑出真实输出就自己跑**（本机有 Docker / MySQL / Node 环境时优先），画面上给真实结果比抄书更有说服力。跑不了再退回第 ① 条。

### 4.2 版权红线

- **代码 / 命令 / SQL**：属事实性内容，**可直接上屏**，但**必须标注出处**（原书页码 + 章节）；**照搬超 30 行连续代码须截取**
- **书中图表 / 插图**：**严禁直接截取书页像素**——一律走「重绘上屏 + 标据原书 P.N 重绘」
- **官方原图**：走官方渠道获取，标「来源：官方文档 <URL>」
- 所有素材入画前过**去侵权检查**（`visual-design.md` §4：第三方水印 / 版权角标 / 无关Logo / 网址域名）

## 5. 排版与字幕带（与既有硬约束的联动）

- 实战载体（代码块 / 终端块 / 图示 / 表格）主体**必须收在画面顶部 85% 安全区内**，下方留字幕带
- **代码块底部与字幕带至少留 24px 空隙**——**字幕严禁压在代码上**，代码块是实战内容的核心载体，被盖住等于该段白做
- 深/浅代码块**全片只用一种**（`code-on-screen.md` §1.2）
- 合成后**抽帧核验**：代码/终端/图示区域无字幕侵入，必要时上调内容或下移字幕带

## 7. 反面案例（勿重犯）

| ❌ 错误 | 为什么错 | ✅ 正确 |
|---|---|---|
| 讲「Vue 的effect 用栈管理 activeEffect」，屏幕只有字幕 + 一个「栈」字 | 用文字描述代码，读者看不到真实结构 | 上屏 `effect.ts` 13 行，**高亮 `activeEffect = prevEffect` 那一行** |
| 讲「MySQL 索引失效的几种情况」，画面是 4 个文字方框 | 排查类内容必须看到**怎么查** | 终端块 + `EXPLAIN` 真实输出，**高亮 `type: ALL`** |
| 讲「双端 Diff 推进过程」，一张静态图带 4 个箭头 | 过程压成了单图，读者跟不上推演 | 4 帧分步序列，**每帧只推进一个指针** |
| 讲「服务端渲染多一次序列化」，画了个自创的方框图 | 自创图丢了原书细节，且没标出处 | 重绘原书 P.112 流程图，标「据原书 P.112 重绘」 |
| 讲算法复杂度，给出复杂度公式但**没给实例推演** | 抽象公式读者记不住 | 逐行公式推导 + **输入→中间态→输出**实例数据 |
| 讲 API 怎么用，只念参数表 | 参数表在嘴里，代码在屏幕上 | P0 代码块 + 关键行高亮 |
| 讲「按 3 个 key 练习重排」这种伪代码 | 伪代码不是真实源码，讲了也没法用 | 给书中真实 Diff 实现代码 |
