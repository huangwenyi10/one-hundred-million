# 实战类内容视觉化规范（全训练营通用 · 强制）

> **适用范围（2026-10-07 起由「读书训练营」扩至全部 9 大训练营）**：作者指令原文——「除了读书训练营，其他的训练营，也要按需把**代码示例、图表、架构图、流程图**等等放进视频里面，不要纯文字口述」。本规范对**架构师 / 大数据 / AI / 产品经理 / 前端 / 测试 / 管理 / 软技能 / 读书**九类训练营**一律强制生效**。§1.2 的「整本实战书」判据相应扩为「本期是实战类主题」——管理/软技能/产品类同样可能整期都是实战（方法论演练、流程拆解、案例复盘），照样按逐段配载体的标准执行。
>
> 落地背景（2026-10-06，读书营首现）：作者指出「如果书籍是实战类的，或者内容有实战类的，要按需把实战内容或者图表、代码、演示表现出来，让读者能够清楚理解」。此规范把「上屏」从**只针对代码**扩展到**全部实战载体**——代码只是其中一种，架构图、SQL、执行计划、终端操作、公式推导、对比实验、完整案例同样必须上屏。

## 1. 实战类内容的识别（强制判定 · 全训练营）

### 1.1 什么算「实战类内容」

命中任一即为实战类，**必须按 §2 配视觉载体**（判定标准与训练营无关；右列是各训练营的典型场景）：

| 类别 | 特征 | 各训练营典型场景 |
|---|---|---|
| **代码实现类** | 给出函数 / 类 / 模块的实现、调用、改造 | 前端·框架源码/hooks；AI·模型推理代码；大数据·Flink 作业；测试·自动化脚本 |
| **命令操作类** | 给出可执行的 shell / SQL / 命令行 | 大数据·Hive/Spark 作业提交；架构师·Docker/K8s 运维；AI·环境部署 |
| **系统设计类** | 给出架构方案、组件划分、部署拓扑、容量估算 | 架构师·微服务拆分；AI·RAG 系统架构；大数据·数仓分层设计 |
| **数据处理类** | 给出 SQL、索引、查询计划、执行流程 | 大数据·数仓建模与调优；产品·埋点分析 SQL；测试·数据准备 |
| **配置调优类** | 给出配置文件、参数、参数间权衡 | 架构师·网关/缓存配置；大数据·Flink checkpoint 调参；前端·构建配置 |
| **算法推演类** | 给出步骤、递推、状态转移、公式 | AI·注意力/LoRA 推导；大数据·调度算法；测试·覆盖率算法 |
| **案例复盘类** | 给出真实案例的来龙去脉、数据、结论 | 架构师·故障复盘；产品·竞品拆解；管理·项目复盘；软技能·沟通案例 |
| **对比选型类** | 给出方案 A/B 的数据与取舍依据 | 架构师·缓存选型；AI·模型选型；产品·方案对比 |
| **公式定理类** | 给出公式、定理、推导过程 | 架构师·容量估算；大数据·成本公式；管理·期望值/ROI |
| **工具实操类** | 给出工具的操作流程、界面、配置 | 产品·原型工具；测试·测试平台；管理·OKR 工具流；软技能·会议流程 |

### 1.2 本期整体是实战类时

若**整期内容**属实战类（如架构师·一次 K8s 故障排查、AI·手写 RAG 检索链、前端·读框架源码、大数据·调一条慢 SQL、产品·完整案例拆解、管理·一次完整复盘），则：

- **默认整片都应有代码 / 图示 / 演示页**，不是「按需」而是「**逐段按需**」——每一段实战内容配一段对应视觉
- **纯文字页占比上限收紧到 30%**（比通用 40% 更严）
- **每期至少 25% 的页面是代码页或图示页**

若**只有部分段落**是实战类，则只对该部分强制，其他段落按通用规范。

## 2. 实战视觉载体清单（按优先级选）

判断顺序：**从下往上选第一个可行的**。越靠上越能让读者「看懂并跟着做」。

| 优先级 | 载体 | 适用 | 画法 |
|---|---|---|---|
| **P0** | **可运行代码** | 函数 / 类 / 模块 / API / 配置 | 真代码 + 语法高亮 + 关键行高亮 + 出处（`code-on-screen.md` §1） |
| **P0** | **命令与输出** | 终端操作、SQL 执行 | 终端样式块，**提示符 + 命令 + 真实输出**三段齐全，输出高亮变化行 |
| **P0** | **SQL + 执行计划** | 数据库 / 数仓主题 | 左SQL 右执行计划或结果集，关键扫描行标注；**数据量级来自可溯源来源**（原书 / 官方文档 / 本机实测） |
| **P1** | **架构图 / 流程图** | 系统设计、调用链、请求流程（**全训练营最高频载体**） | 优先官方架构图（标URL）或重绘（读书营标「据原书 P.N 重绘」）；用模板 `.diagram-grid` / `.flow`，**禁手写绝对定位** |
| **P1** | **状态机 / 时序图** | 生命周期、状态转移 | 重绘，节点与箭头标注事件 |
| **P1** | **数据图表** | 性能对比、基准测试、容量 | 柱状 / 折线（`visual-design.md` §2.2/2.3），**保留原始数值 + 标来源** |
| **P1** | **对比表** | 方案选型、优缺点 | 对比表版式（`visual-design.md` §2.1），**保留原始数值与结论** |
| **P2** | **分步演示序列** | 操作系统、工具实操、界面操作 | 2~4 帧连续画面，**同一构图的渐变序列**，配「①→②→③」步骤标 |
| **P2** | **公式推导** | 算法复杂度、容量估算、定理 | 逐行推导，每步只高亮新增项；数学符号用等宽或数学字体 |
| **P2** | **实例数据推演** | 算法步骤、状态变化 | 输入 → 中间态 → 输出，**中间态逐个展示**，不是只给最终答案 |
| **P3** | **手写推演纸样式** | 算法、状态机的手工推导 | 浅色横线纸背景 + 手写感字体，营造「演算」现场感 |
| **P1** | **数据面板 / 指标卡** | 性能、容量、成本、留存等量化指标 | 大数字 `.stat.num` + 趋势箭头 + 单位与测试条件标注（口径见 `visual-design.md` §2.4） |
| **❌** | **纯文字罗列** | —— | **一律不合格** |

### 2.1 「演示」的表现形式（作者明确提到）

实战内容里的**操作过程**不该只用一张静态图，而应体现**过程**。三种做法：

1. **分步序列帧**（推荐）：同一主体在2~4 个关键步骤的截图/重绘帧，连续呈现，帧间加箭头或步骤序号 `①②③`
2. **代码逐步高亮**：全屏代码，讲解到哪一行哪一行高亮 —— 静态图 + 合成时的Ken Burns 配合
3. **前后对比**：同一场景「改动前 / 改动后」并排，差异行高亮

**禁止**：把过程压成一张图然后用口播描述过程（等同于「用文字描述代码」的老毛病）。

## 4. 素材来源与版权

### 4.1 优先级链

```
⑤ 本机实跑生成真实输出（终端块 / 结果集）—— 最可信，一律优先
① 原书代码 / 命令 / SQL / 图表  →  提取为文本或重绘上屏（标「原书 P.N 重绘」）
①' 官方文档 / 官方仓库的代码、SQL、配置  →  摘录上屏（标「来源：官方文档 <URL>」）
② 官方文档配图 / 官方博客架构图  →  裁切去水印后上屏（标来源 URL）
③ 授权素材（明确可商用，留凭证）
④ 自行重绘（忠于概念不复制像素）
```

**第⑤条实战价值最高**：命令 / SQL / 样例**能在本机跑出真实输出就自己跑**（本机有 Docker / MySQL / Node / Python 环境时优先），画面上给真实结果比抄书更有说服力。跑不了再退回上方来源。**这条对全部 9 大训练营一致**——不只是读书营。

### 4.2 版权红线

- **代码 / 命令 / SQL / 配置**：属事实性内容，**可直接上屏**，但**必须标注出处**（读书营＝原书页码+章节；其他营＝官方文档 URL/章节，或本机实跑环境）；**照搬超 30 行连续内容须截取**
- **书中图表 / 插图**：**严禁直接截取书页像素**——一律走「重绘上屏 + 标据原书 P.N 重绘」
- **官方文档/博客配图**：走官方渠道获取，标「来源：官方文档 <URL>」；**不得当自己原创产出**，不得抹掉水印冒充原创
- 所有素材入画前过**去侵权检查**（`visual-design.md` §4：第三方水印 / 版权角标 / 无关Logo / 网址域名）

## 5. 排版与字幕带（与既有硬约束的联动）

- 实战载体（代码块 / 终端块 / 图示 / 表格）主体**必须收在画面顶部 85% 安全区内**，下方留字幕带
- **代码块底部与字幕带至少留 24px 空隙**——**字幕严禁压在代码上**，代码块是实战内容的核心载体，被盖住等于该段白做
- 深/浅代码块**全片只用一种**（`code-on-screen.md` §1.2）
- 合成后**抽帧核验**：代码/终端/图示区域无字幕侵入，必要时上调内容或下移字幕带

## 7. 反面案例（勿重犯 · 读书营与非读书营各半）

| ❌ 错误 | 为什么错 | ✅ 正确 |
|---|---|---|
| 讲「Vue 的effect 用栈管理 activeEffect」，屏幕只有字幕 + 一个「栈」字 | 用文字描述代码，读者看不到真实结构 | 上屏 `effect.ts` 13行，**高亮 `activeEffect = prevEffect` 那一行** |
| 讲「MySQL 索引失效的几种情况」，画面是 4 个文字方框 | 排查类内容必须看到**怎么查** | 终端块 + `EXPLAIN` 真实输出，**高亮 `type: ALL`** |
| 讲「双端 Diff 推进过程」，一张静态图带 4 个箭头 | 过程压成了单图，读者跟不上推演 | 4 帧分步序列，**每帧只推进一个指针** |
| 讲「服务端渲染多一次序列化」，画了个自创的方框图 | 自创图丢了原书细节，且没标出处 | 重绘原书 P.112 流程图，标「据原书 P.112 重绘」 |
| 讲算法复杂度，给出复杂度公式但**没给实例推演** | 抽象公式读者记不住 | 逐行公式推导 + **输入→中间态→输出**实例数据 |
| 讲 API 怎么用，只念参数表 | 参数表在嘴里，代码在屏幕上 | P0 代码块 + 关键行高亮 |
| 讲「按 3 个 key 练习重排」这种伪代码 | 伪代码不是真实源码，讲了也没法用 | 给书中真实 Diff 实现代码 |
| **【非读书营】讲「K8s 探针配置怎么调」，画面只有一段 `readinessProbe` 的文字描述** | 同Vue 那条一模一样的病：**用文字描述代码**。配置类内容必须看到真实的 YAML/配置片段 | 上屏真实 `deployment.yaml` 片段 12 行，关键参数（timeoutSeconds/failureThreshold）高亮，标 `来源：官方文档 <URL> · Configure Liveness, Readiness and Startup Probes` |
| **【非读书营】讲「限流算法有哪几种、各自代价」，画面是三个文字方框** | 对比选型类必须看到**判别依据**，纯罗列名字等于没讲 | 对比表版式（`table.cmp`）：算法 / 复杂度 / 突发容忍 / 实现成本四列，数值取自官方文档或实测 |
| **【非读书营】讲「一次线上故障的排查过程」，只有时间线文字** | 案例复盘类必须看到**排查动作链**，不是只报结果 | 分步序列 4 帧（监控告警→定位指标→读配置→扩容恢复），同一构图的渐变，每帧标 `①②③④` + 具体命令/指标名 |
| **【非读书营】讲「大模型 RAG 的检索链路」，画面是竖排 4 个方框加箭头** | 架构图丢掉了分层的关键细节（切分/向量化/召回/重排/拼装），且没标来源 | 重绘分层架构图：离线链路（切分→向量化→索引库）与在线链路（查询→召回→重排→拼装）分区着色，标 `来源：官方文档 <URL>` |
