# 训练营生成开关（camp switch · 固定规范 · 强制）

> 决策来源：作者 2026-10-01 ——「除了读书训练营继续按照定时任务执行，其他的训练营先暂停，生成的视频质量太差了，可以做成开关，下午我说开始，再开始」。
> 配套脚本：`scripts/camp_switch.py`（仅标准库）。状态文件：工作区根目录 `camp_switches.json`。

---

## 一、默认策略

| 训练营 | 默认状态 |
|--------|----------|
| **读书训练营** | **ON（常开）** —— 继续按定时任务产出，不受本开关暂停 |
| 架构师 / 大数据 / AI / 产品经理 / 前端 / 测试 / 管理 / 软技能 | **OFF（暂停）** —— 不生成、不轮转、不做选题 |

**暂停的含义是「完全不产出」**：不选题、不写口播稿、不渲帧、不配音、不入目录、不写 `metrics.csv` 正片记录。不是「少做」，是「不做」。

## 二、状态文件

- 路径：`<工作区>/camp_switches.json`。
- **文件不存在 = 使用默认策略（只开读书训练营）**——首次运行不需要预先建文件。
- 格式：

```json
{
  "version": 1,
  "updatedAt": "2026-10-01T21:31:07+08:00",
  "policy": "default-only-reading-camp",
  "enabled": ["读书训练营"],
  "history": [
    {"ts": "2026-10-01T21:31:07+08:00", "action": "off", "camp": "架构师训练营", "note": "作者要求暂停"}
  ]
}
```

- `enabled` 只需列出**启用**的营；未列出 = 暂停。顺序由脚本按固定 9 类顺序归一，写成数组时不需要自己排序。
- `history` 保留最近 30 条变更（谁在什么时候开了/停了什么），供事后追溯「为什么这个营没产出」。

## 三、脚本用法

```bash
S=scripts/camp_switch.py

python3 $S status                      # 打印 9 营开关表（含启用数 / 状态文件来源）
python3 $S status --json               # 机器可读
python3 $S list-enabled                # 逐行打印启用营
python3 $S check "<训练营全名>"         # 门禁：启用 exit 0 / 暂停 exit 3
python3 $S on  <营名> | on --all        # 开启单个 / 全部
python3 $S off <营名> | off --all       # 暂停单个 / 全部
python3 $S next [--rotation FILE]      # 算本期应做的营（stdout）；启用集合为空 exit 4
python3 $S reset                       # 恢复默认策略（只开读书训练营）
```

- 通用选项 `--workspace <dir>`（默认当前目录）、`--note "<说明>"`（写入 history）放前放后都可用。
- 营名支持简称/别名：`架构师` / `大数据` / `ai` / `产品` / `前端` / `测试` / `管理` / `软技能` / `读书`（无法识别 → exit 2，不会静默改错）。
- 退出码约定：`0` 启用·成功；`2` 参数错误；`3` 该营已暂停（门禁拦截）；`4` 启用集合为空（本轮无内容可做）。

## 四、开工门禁（强制 · 任何生产前第一步）

**任何一次生产开工（含定时任务、含作者临时点题）都必须先过这道闸：**

```bash
python3 scripts/camp_switch.py check "<本期训练营全名>"
```

- `exit 0` → 放行，继续 Step -1（模型挑选）与 Step 0（选题）。
- `exit 3` → **立即停止本轮**：不写口播稿、不渲帧、不配音、不入目录。只在日志与 `metrics.csv` 备注写一行 `暂停跳过：<营名> <时间>`，然后结束。
- **禁止「先做出来再说」**，禁止以「素材已就绪 / 时间已排期 / 热点正好」为由绕开开关。技能自主决策权（固定规范第 16 条）**不覆盖**本开关。

## 五、定时轮转适配

轮转不再无条件按 0→8 推进，而是**只在「启用营集合」内推进**（脚本 `next` 子命令实现）：

1. 读 `camp_switches.json` 的 `enabled`（不存在 → 默认只含读书训练营）。
2. 读 `one-hundred-million-rotation.json` 的 `lastCategory`，在启用集合里取它的下一个（到尾部回卷到头部）；`lastCategory` 不在启用集合内 → 取启用集合第一个。
3. `enabled` 为空 → `exit 4`，本轮**不生成任何内容**，记一行日志退出。

**默认策略下的实际效果**：启用集合只有读书训练营，所以每次调度都产出读书训练营（按「一书三分」批量出上/中/下），其余 8 类不占用调度。**恢复全部营后**，轮转自动回到 9 类顺序推进，无需手工改轮转状态文件。

## 六、作者口令 → 动作映射（唯一恢复途径）

| 作者说法 | 执行 |
|----------|------|
| 「开始」「可以开始了」「都恢复吧」「继续做 XX 营」 | `camp_switch.py on --all`（或 `on <营名>`） |
| 「先停 XX 营」「XX 营别做了」 | `camp_switch.py off <营名>` |
| 「停掉其他的，只留读书营」「恢复默认」 | `camp_switch.py reset` |

- **只有作者明确发话才改开关**。没有口令时，暂停的营保持暂停——不得因为「轮转轮到它了」「热点正好」自行恢复。
- 改完开关**要把「现在开了哪些营」回给作者**（贴 `status` 输出或启用清单），让作者一眼看到当前状态。
- 若作者说「开始」但未指定营 → 按「全部开启」处理（`on --all`）；不确定时先回一句确认再动手。

## 七、读书训练营保护

- 读书训练营是默认常开项。`off 读书训练营` 属于**高危操作**——会让账号完全断更。
- 仅当作者**明确点名**要停读书营时才执行；执行后在回复里显式提示「读书训练营已暂停，账号将无新内容产出」。
- `camp_switch.py` 在读书营被关掉时会主动打印 `⚠️ 注意：默认常开的「读书训练营」当前处于暂停状态` 作为二次提醒。

## 八、与其它状态文件的关系

| 文件 | 职责 | 与开关的关系 |
|------|------|--------------|
| `camp_switches.json` | **能不能做**（本文件） | 最上层闸门，先过它 |
| `one-hundred-million-rotation.json` | 9 类轮转推进到哪 | 在启用集合内推进（`next`） |
| `one-hundred-million-syllabus.json` | 各营能力维度覆盖进度 | 只对启用的营读写 |
| `reading_camp_progress.json` | 读书营当期书与分部 | 读书营常开，正常读写 |

## 九、排障

- **看到某营「莫名不产出」** → 先 `status` 看开关，再看 `history` 里是谁在什么时候关的。
- **`check` 报 exit 3 但作者说已恢复** → 多半是工作区不对（状态文件按工作区存放，切了工作区就读不到）；确认 `--workspace` 与 `status` 输出的路径。
- **状态文件损坏** → 脚本会打 `[WARN]` 并回落默认策略（只开读书训练营）；确认后用 `on/off` 重写即可，不会因损坏而放开全部营。
- **想全局恢复出厂** → `reset`。
