# 口播稿写作规范（自媒体短视频）

## 基本参数

- 长度：与目标档位匹配（档位由「讲透优先 + 认知负载」自主裁定，见 `content-formats.md` 档位决策矩阵）。按 260 字/分钟估算：S 档 60–90 秒 ≈ 250–400 字；M 档 3–5 分钟 ≈ 750–1300 字；L 档 15–30 分钟 ≈ 3800–7600 字；读书营一部 ≥30 分钟。**不要默认全写 M 档——该长的要长（L 档讲透体系），该短的要短（S 档只讲一个结论）。**
- 标题：≤ 20 个字，优先用"数字 + 结果"公式（例：Doris存算分离：成本直降90%的秘密）。
- 格式：可直接复制进 Word 的连续段落，一段一个完整意思，不要频繁换行、不要小标题、不要列表。

## 结构模板（按档位选择，不都是通读式）

> 结构模板**分档**（见 `content-formats.md`）：S 档「钩子→单点结论→一句为什么→CTA」；M 档「钩子→痛点→原理四段闭环→坑/边界→结论+CTA」；L 档才用下方通读式。**每个核心概念走完「是什么→为什么→怎么做→数据/案例」讲透闭环，禁止罗列式、禁止只给结论/方案不给原理。**

1. 开场（固定）：`大家好，我是Map。` 紧接一句话点出本期主题 + 一个抓人的钩子（数字、反常识、痛点）。
2. 主体：沿资料原有叙事顺序展开——背景/痛点 → 现状方案及问题 → 转折点 → 新方案（架构/原理） → 数据验证（性能/成本） → 用户案例 → 总结展望。
3. 结尾（自然收尾 + CTA，**禁止固定结束语模板**）：结尾不出现"以上就是今天所有内容，感谢大家观看，我们下期再见"等固定收尾句（任何变体都不允许）；用一句话总结本期核心结论或呼应开头钩子，再接引导关注/评论的 CTA（话术见 `hooks-and-cta.md`）。

## 口语化技巧

- 用"咱们""这块""说白了""注意了""划重点"等口头衔接，但每篇同一口头禅不超过 3 次。
- 长句拆短句，一句一个信息点；技术名词第一次出现用大白话解释一次。
- 每隔 1–2 分钟埋一个钩子（提问、悬念、转折），维持完播率。
- 数字要念得顺口："百分之九十"优于"90%"；金额保留原始精度（$36962.7）以显真实。

## AI 味特征清单（写完逐条排查，命中即改）

1. 排比三连："更X的是…更X的是…更X的是…"。
2. 空洞总结词："总而言之""综上所述""值得注意的是"。
3. 对称句式堆砌："既是机遇，也是挑战"式的万能对仗。
4. 过度连接词：每段开头都是"首先/其次/最后/然而/因此"。
5. 夸张形容："革命性的""颠覆性的""无与伦比"（除非资料原文有数据支撑）。
6. 机器人式罗列：不带语气、不带节奏的名词堆叠。
7. 转述腔："据资料""文中提到""附件指出"——一律删除，改为第一人称直接陈述。

## 训练营分类话术基调

| 类型 | 基调 | 开场钩子示例 |
|------|------|--------------|
| 架构师 | 深度、判断力、踩坑经验 | "这个架构决策，让XX公司省了XX万" |
| 大数据 | 数据规模冲击、成本账 | "PB级数据，每月成本只要XXX美金" |
| AI | 前沿、快速迭代、动手 | "这个模型上线三天，效果翻倍" |
| 前端 | 体验、性能、新特性 | "首屏快了3倍，就改了这一处" |
| 产品 | 用户、增长、取舍 | "这个功能上线后，留存涨了XX%" |
| 测试 | 质量、效率、自动化 | "从3天到3分钟，自动化测试这么玩" |
| 管理 | 协作、决策、复盘 | "带团队第一年，我踩过的5个坑" |
| 软技能 | 共鸣、成长、职场 | "为什么技术好的你，晋升总轮不到" |

## 事实性红线

- 性能数字、成本金额、客户名单、版本号只能来自资料原文或可验证的公开信息。
- 拿不准的结论宁可删掉，不做推测性断言。
- 网络检索来的信息需两个独立来源交叉验证后方可使用。
