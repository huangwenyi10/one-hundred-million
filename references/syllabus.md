# 训练营体系 · 开放能力地图（看完成为专家 · 章节无穷）

## 核心约定

- 每个训练营 = **一套体系化能力**，读者跟着看完这一整个训练营，应能成为该领域的专家（架构师训练营 → 架构师；大数据训练营 → 大数据专家；产品经理训练营 → 产品经理；AI / 前端 / 测试 / 管理 / 软技能同理）。
- **章节是无穷的，不存在一份固定目录。**下面每一类给出的「能力维度 + 示例主题」只是**思路提示**，不是边界、不是待办清单、不是必须按顺序讲完的章节。真实选题由技能按「体系连贯 + 热点切口」自主延展——任何新角度、新技术、新案例、新痛点都可以随时长出来，不必预列入表。
- 体系化的抓手不是「固定编号的节」，而是两点：**①覆盖专家能力地图的不同维度**（不长期扎在一个窄点、不整块能力空白）；**②内容前后承接**（这一条与已讲内容递进 / 互补 / 呼应，不是游离的孤立知识点）。
- 进度文件 `one-hundred-million-syllabus.json` 记录「已覆盖的主题节点」（`covered` 开放关键词列表），用于**去重与决定下一期往哪个维度延展**，不锁定任何章节。表中的示例主题若已过期、已被新技术取代，技能可直接用更合适的当下主题替代，无需回写本文件。
- **AI 视角优先 + 实战优先（2026-09-13 起，强制）**：
  - **AI 视角优先**：每个训练营选题时**优先考虑能否挂上「AI 赋能 / AI 在 X 的应用 / AI 时代 X 怎么做」的视角**——AI 是当下最热的技术趋势，每条内容能挂上 AI 视角就挂，让观众一眼就觉得「这门课跟得上时代」。但**不是所有内容都必须是 AI**：纯算法溯源、纯历史理论、纯硬件物理等无法挂 AI 视角的，不强求——「尽量和 AI 靠」是努力方向，不是内容本身的强制。
  - **实战优先（禁止纯方法论）**：每条内容必须有**实战案例 / 真实项目拆解 / 跑得通的方案 / 有名有姓的数据与公司**——禁止「讲一堆原则却给不出怎么落地」。方法论不是不能讲，但**方法论必须配实战**（至少 1 个真实案例 / 真实跑通的方案 / 有名有姓的数据），否则判为不合格。这条与「工匠级品控」中「案例 / 数据有名有姓」「每个结论讲透为什么」联动——不是「空讲一招」而是「讲了为什么并跑通过」。
  - **实战形态与判据以 SKILL.md 固定规范第 31 条② 为准**（代码/命令/配置片段、工具/平台操作演示、真实案例拆解、真实踩坑复盘——四者至少满足其一）。本节只负责**选题方向**与**配比**，不另立口径，避免两处打架。
  - **实战选题方向（每个训练营的优先切口 · 示例非穷举 · 2026-10-01 新增）**：
    - **架构师** → 亲手复现一次线上雪崩 / 用压测把 QPS 打到拐点 / 做一次容量估算并复盘偏差 / 拆一个开源项目的真实部署结构
    - **大数据** → 亲手跑出一次数据倾斜并修掉 / 真实表上做一次分区与索引对比 / 算一笔存储与计算成本账 / 搭一条最小 CDC 同步链路
    - **AI** → 跑通一个最小可用 RAG / 做一次提示词对比实验 / 微调小模型并看 loss 曲线 / 用评测集给两个模型打分
    - **前端** → 用 Performance 面板定位一次真实卡顿 / 亲手把首屏指标优化若干个百分点 / 做一个跨端适配最小 demo / 复现一次内存泄漏
    - **测试** → 亲手复现一个 Flaky 用例并定位根因 / 写一个能拦住历史 bug 的用例 / 搭一次稳定的 CI 测试流水线 / 做一次接口自动化改造
    - **产品** → 用真实数据做一次留存或漏斗拆解 / 亲手写一份 PRD 的关键章节 / 做一次 A/B 实验设计与结果解读 / 复盘一个被砍掉的功能
    - **管理** → 亲手做一次 1:1 复盘表 / 用真实数据校准一次 OKR / 复盘一次延期并改流程 / 做一次团队效能度量
    - **软技能** → 把谈薪 / 汇报 / 拒绝落成可复用话术模板 / 用真实案例拆一次晋升评审 / 做一次表达能力自测
    - **读书训练营** → 锁死书中章节，把书中可操作的方法论与可复现的实验搬进画面（不强制加代码）
  - **动手型配比（强制 · 量化）**：**每 4 期至少 1 期是「动手型」**（含代码 / 命令 / 配置 / 可复算推演这类可操作形态，而非仅案例叙述）；**连续 3 期均为纯叙述型（无任何可操作形态）时，第 4 期必须排动手型选题**。门禁：每期口播稿定稿后跑 `python3 scripts/content_depth_check.py "<口播稿.txt>" --camp <训练营全名>`，**`BLOCK` 未清零不得进入 Step 2**。
- **AI 视角与实战的具体落点**：下面每个训练营的能力维度里，**显式列出「AI 视角 / AI 赋能 / AI 时代能力」一行**——把该训练营能挂上的 AI 应用、AI 工具、AI 改变工作流的维度写明，作为选题优先清单（不是穷举）。选题时从该清单挑一个 + 配实战案例，自然形成「**AI 视角 + 实战案例**」组合。示例主题里优先举**已落地、可用、可复现**的实战项目，避免「假大空」式描述。

## 1. 架构师训练营

**专家目标**：能独立承担系统架构设计、技术选型与关键技术决策的架构师。

**能力维度（示例，非穷举）**：

- 角色与能力模型：架构师职责边界、能力模型、工程师 → 架构师转型路径
- 架构设计基本功：从需求到架构、架构风格选型（单体 / 分层 / 微服务 / 事件驱动）、模块划分与依赖治理
- 高并发：容量估算、缓存体系（多级缓存 / 穿透 / 击穿 / 雪崩）、异步化与削峰填谷
- 高可用与稳定性：冗余与故障转移、熔断 / 限流 / 降级、SLO / SLA 与可观测
- 数据架构：存储选型、分库分表与分片、分布式事务与最终一致
- 分布式与微服务：服务拆分、服务治理（注册发现 / 配置 / 网关）、消息与事件
- 云原生与成本：容器与编排、成本优化、供应商锁定代价
- 架构演进与治理：架构评审、技术债管理、遗留系统改造
- 架构表达与影响力：架构文档与图、方案评审与说服、跨团队推动落地
- **AI 视角与 AI 时代能力（优先维度）**：AI 辅助架构决策与方案生成（用大模型做架构草图 / 选型建议 / 风险扫描）、AI 辅助代码评审与架构合规检查、Agent 驱动的架构可观测与故障定位、AI 时代架构师的能力重构（从画图转向 AI 编排与治理）、AI 工程化对架构的反向影响（推理成本 / 算力调度 / 向量库 / RAG 架构）
- 实战复盘：典型系统拆解、失败案例与踩坑

## 2. 大数据训练营

**专家目标**：能设计并落地企业级数据平台、让数据产生业务价值的大数据专家。

**能力维度（示例，非穷举）**：

- 全景与角色认知：数据工程师 / 分析师 / 平台工程师职责边界、技术栈地图与选型逻辑
- 数据建模与数仓分层：维度建模、分层架构（ODS / DWD / DWS / ADS）、指标体系设计
- 数据采集与接入：日志 / 埋点 / CDC、数据同步与一致性、数据质量与脏数据治理
- 批处理与离线计算：存储底座、计算引擎（Spark 等）、任务调度与血缘
- 实时与流计算：时间语义与窗口、状态与容错（精确一次）、流批一体与实时数仓
- OLAP 与查询加速：MPP 引擎、物化视图与预聚合、即席查询调优
- 数据平台与治理：元数据与数据地图、权限 / 脱敏 / 合规、数据资产与成本治理
- 数据应用与价值：指标体系支撑决策、用户画像与标签、BI 与自助分析
- **AI 视角与 AI 时代能力（优先维度）**：Text-to-SQL / 自然语言查数（NL2SQL）实战、AI 生成 ETL 与数据同步脚本、AI 辅助指标定义与血缘推断、AI 数据质量监控（异常检测 / 漂移检测）、大模型驱动的智能问数与自助分析、向量化与 Embedding 在数据检索 / 用户画像 / 推荐系统的实战、AI Agent 在数据平台运维与故障排查的应用
- 调优实战与成本控制：作业性能调优、故障排查与成本优化案例

## 3. AI 训练营

**专家目标**：能把 AI 能力工程化落地、对效果与成本负责的 AI 工程师。

**能力维度（示例，非穷举）**：

- AI 全景与能力边界：能做什么 / 不能做什么、从模型到应用的全链路技术栈
- 机器学习基础：监督 / 无监督、特征工程、评估与过拟合
- 深度学习基础：训练流程直觉、常见网络结构与适用场景
- 大模型原理：Transformer 与注意力、预训练 / 微调 / 涌现、推理与采样参数
- 提示工程与上下文：Prompt 设计、Few-shot / 思维链、长文本与上下文管理
- RAG 与知识库：文档切分与向量化、检索与重排、效果评测与失效原因
- Agent 与工具调用：规划 / 工具调用 / 记忆、多智能体协作、可靠性（幻觉 / 死循环）
- 训练与微调：数据准备、参数高效微调、评测与对齐
- 推理工程化与部署：推理服务（并发 / 延迟 / 吞吐）、推理优化（量化 / 批处理 / 缓存）、成本控制与可观测
- AI 应用产品化：场景选择、效果评估、安全合规与风险边界

## 4. 产品经理训练营

- **AI 视角与 AI 时代能力（优先维度）**：AI 辅助用户研究（访谈纪要 / 反馈聚类 / 情感分析）、AI 生成 PRD / 原型 / 用户故事与验收标准、AI 辅助竞品分析与市场扫描、Prompt / Agent 驱动的产品工作流自动化、AI 时代的产品差异化（把 AI 能力做成产品核心功能而非噱头）、AI 产品评测与红线（幻觉 / 数据安全 / 偏见）、AI 原生产品的指标体系与冷启动

## 9. 读书训练营

**专家目标**：把经典书籍读透、讲清，用一本书构建一整套认知体系。

**特殊说明**：读书训练营**天然体系化**——书本身就是目录，无需在此列能力地图。它遵循 SKILL.md「读书训练营专项」的**「一书三分」模型**：一本书拆上 / 中 / 下三部，按原书章节顺序推进，每部拆 2–3 条选题。进度走 `reading_camp_progress.json`，不写本文件的 `covered`。**选书来源**：读哪本书以 `references/author-book-list.md`（作者书单）为唯一事实来源——书单有「待录制」的书时优先从书单顺序取，不自由选书（详见 SKILL.md「作者书单优先」）。

## 进度文件 `one-hundred-million-syllabus.json`

存放于工作区根目录，记录 8 类技术 / 职业训练营的体系推进位置（读书训练营走 `reading_camp_progress.json`，不写这里）。

```json
{
  "架构师训练营": {
    "expertGoal": "能独立承担系统架构设计、技术选型与关键技术决策的架构师",
    "lastTopic": "缓存体系：多级缓存与穿透 / 击穿 / 雪崩",
    "covered": ["架构师职责边界", "能力模型", "从需求到架构", "架构风格选型", "容量估算", "缓存体系"]
  },
  "大数据训练营": {
    "expertGoal": "能设计并落地企业级数据平台、让数据产生业务价值的大数据专家",
    "lastTopic": "",
    "covered": []
  }
}
```

字段说明：

- `expertGoal`：该训练营的专家目标（与本节能力地图一致，选题时对齐）。
- `lastTopic`：上期讲到的主题关键词，用于本期内容承接。
- `covered`：已覆盖主题节点关键词列表（**开放、非固定编号、唯一事实来源**）——用于去重（不重复已讲）与决定下一期往哪个尚未充分覆盖的维度延展。

**选下一主题的规则**：

- 优先往 `covered` 尚未充分覆盖的能力维度延展，保持体系推进、不长期扎在一个窄点、不整块能力空白（如只讲前端不讲测试）；
- 当期热点 / 新数据能映射到某维度时，切入该维度讲（仍属体系内，非游离）；
- 已讲主题不机械重复；若换角度 / 新数据重讲，在 `covered` 中以「主题 + 角度」区分，不静默覆盖。

本文件只记录「已讲到哪、覆盖哪些维度」，**不限制还能讲什么**——章节无穷，体系永远在生长。
