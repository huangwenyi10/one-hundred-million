# 工匠级品控规范（Craftsmanship Quality）

> 目标：把短视频从「能看、能发布」提升到「**工匠级成品**」——内容、音频、动画、字幕、画面**每一个环节**都经得起放大镜审视，作者看完挑不出「这里能不能再改改」。
>
> 定位：本文档是**既有规范的进阶增量，不是替代**。基础质量门禁照旧——讲透闭环（`content-formats.md`）、四方同频（SKILL.md 第 11 条 + `check_sync.py`）、专业视觉版式（`visual-design.md`）、去 AI 味（`script-writing-guide.md`）、事实正确（SKILL.md 第 7 条）。本文档只讲**在这些「及格线」之上，怎么做到「优秀」**，并驱动技能**持续进化**。

---

## 0. 工匠精神总纲

- **精益求精 = 拒绝「能用就行」，追求「挑不出毛病」**。任何一处「差不多」都是瑕疵，回炉修到零瑕疵才交付。
- **质量覆盖全链路**：内容、音频、动画、字幕、画面、节奏——**没有哪个环节可以「凑合」**，一个环节掉链子，整条就是流水线货，不是工匠活。
- **三个自问**（每次交付前问自己）：
  1. 这个数字 / 案例，读者信吗？**有名有姓、有出处吗？**
  2. 这一帧、这段音频、这条字幕，**放大看 / 精听**有没有瑕疵？
  3. 这一句，能不能**更顺、更准、更打动人**？
- **工匠标准**：读者看完能**复述**出一个核心收获（一个结论 / 一个数字 / 一个反常识），而不是「讲了一堆名词，啥也没记住」。
- **永不满足**：这次做到 90 分，下次目标 95 分。技能不是静态的，是**越用越精**的活体（见 §7 持续进步）。

## 1. 内容工匠（把话讲到读者心里）

### 1.1 颗粒度——案例/数据「有名有姓」
- 真实公司名 / 产品名 / 版本号 / 具体数字直接写出（如「Doris 3.0 读写分离，成本降 90%」），**禁止「某大厂」「提升了 N 倍」「某头部公司」式模糊表述**。
- 数据拿不到精确值时**明确留白**（「官方未公开」），不编一个「看起来合理」的约数。

### 1.2 机制解释——每个结论讲「为什么」
- 不是「它更快」，而是「因为做了 X，所以快了 Y」——读者要的是**可迁移的因果链**，不是结论堆砌。
- 讲透闭环（是什么→为什么→怎么做→数据/案例）里的「为什么」这一环，工匠级要求**落到机制层**，不是一句「因为优化了」。

### 1.3 类比质量——把抽象讲成「秒懂的画面」
- 抽象概念必须配一个**读者熟悉的类比**（生活场景 / 日常工作），且类比**准确**——不偷换概念、不误导。
- **一个类比用到底**，中途不换比喻；类比之后**立刻回扣**到技术真实含义（「类比只是为了好懂，真实机制是……」），避免读者把类比当真。

### 1.4 记忆点——每条留一个「可复述」的钩子
- 每条视频至少留 **1 个读者看完能复述给别人听的记忆点**：一个金句 / 一个反常识数字 / 一个精炼结论。
- 这个记忆点要**在前 3 秒埋下、结尾呼应**，形成闭环记忆。

## 2. 视觉工匠（每一帧都耐看）

### 2.1 视觉焦点唯一
- 一屏**只有一个视觉焦点**（最大、最亮、最突出），其余元素弱化衬托；读者视线 **1 秒内**找到重点。
- 焦点不唯一 = 画面没有主次 = 失败，拆屏或弱化。

### 2.2 层级对比
- 标题 / 结论字号 **≥ 正文 2 倍**；关键数据放大到「无法忽略」（大数字 / Stat 页）。
- 颜色、字号、粗细三重手段拉开层级，禁止「全屏一样大、一样粗」。

### 2.3 留白呼吸感
- 画面留白 **≥ 20%**，不塞满；信息偏多就**拆屏**（一屏一个焦点），不压缩到密不透风。

### 2.4 配色克制
- 全片主色 **≤ 3 种**（训练营高亮色 + 中性色 + 白），强调色**只在「结论 / 数据」处**出现，不滥用高亮。

### 2.5 对齐精确
- 卡片 / 图标 / 文字边缘**像素级对齐**（同行等高、等间距、边缘对齐），无 1px 错位感；圆角、描边、阴影风格全片统一。

## 3. 动画工匠（动起来，且动得漂亮）

> 动画的工匠标准：**服务于理解，节奏跟配音，缓动自然，帧率流畅，克制不炫技**。设计纪律见 `visual-design.md` §3，本节讲「怎么算动得好」。

### 3.1 节奏跟配音（最高优先级）
- 要点渐入 / 卡片推进 / 数字弹出**必须与配音讲到该处的节奏一致**——配音讲到哪，画面动到哪，不抢跑、不滞后、不一次性提前全显。
- 一次性讲完的内容就一次性显示，**不要**逐条卡在配音前。

### 3.2 缓动自然
- 用标准缓动函数（ease-out / cubic-bezier 平滑曲线），**不生硬、不抽搐、不弹过头**；数字滚数用缓出收尾。

### 3.3 帧率流畅
- 动画帧导出 **≥24fps**，无卡顿、无跳帧、无闪烁；关键页动画全程捕获进成片（走 `render_animated.js`），不是只有静态终点态。

### 3.4 克制不炫技
- 单页动效 **≤2 处**；总动画时长 **≤ 该页停留的 20%**；动画为逻辑服务，能静讲清的不加动效。
- 镜头运动（Ken Burns）缓慢自然，zoom 1.00→1.06 级别（`--preset 1`），缓动用 smoothstep（两端速度为 0，起停不跳），不眩晕。

### 3.5 结束态可读
- 动画结束（`forwards`）后内容**完全静止可读**，不在运动中间结束一页；静态帧导出下每页即使无动画也完整表达。

### 3.6 编码质量（不引入压缩瑕疵）
- **禁止二次有损**：合成中间段（Ken Burns 单段 / 动画帧序列）必须用**无损暂存**（x264 `qp 0` 或 `crf 0`），仅最终一次有损编码（`crf ≤18`，`preset medium`）；**严禁「逐段 crf20 再 xfade crf20」的二次有损**——渐变背景（封面 / 训练营主色块）会出现 H.264 色带 / 块化，是「画面脏」的头号来源。
- **Ken Burns 直接用 1920×1080 源帧做亚像素采样，不要再预放大**：`perspective` 的四角坐标本身是浮点，直接对 1080p 源做「裁剪 + 缩放」即可；**禁止 `scale=8000:-1` 之类盲目 4× 放大再压回**（全片文字 / 线条发虚），**也禁止再按最大 zoom 预放大**（`scale=trunc(iw*Z/2)*2`）——那是 zoompan 时代的补丁，多一次重采样会让每个运动段起始帧都比原图软（实测锐度 55.8 → 直采为 73.5）。缩放放大倍率上限 = zoom 峰值（1.06/1.10/1.16）。
- **CSS 动画进视频**：无头 Chrome 捕获必须启用 SwiftShader 软件渲染、**禁用 `--disable-software-rasterizer`**（否则 transform/opacity 动画被丢弃、页面变静态）；截屏按**累计目标时间戳**调度（非固定 `sleep`），保证 ≥30fps 无抖动、无跳帧。

### 3.7 亚像素运动 + 整数帧对齐（消除「画面抖」）
> **这一节是「画面抖」的唯一权威定义与修复口径（2026-09-10 重写）。** 旧版只盯「转场 offset 整数帧 / 三角波连续」，实测**成片依然抖**——因为抖动根因不在转场，而在**镜头运动本身被量化**。

- **镜头运动必须走 `perspective` 亚像素采样，禁止 `zoompan`（强制）**：`zoompan` 会把裁剪窗口的**尺寸与位置截断到源图像素的整数格点**。本项目单帧位移只有 **0.1~0.5 px**，远小于 1 个源像素 → 运动被量化成「连续 3~4 帧完全静止 + 突然跳 1 像素」，文字/线条边缘每跳一次就是一次重定位，肉眼即「画面抖 / 一顿一顿」。
  - **实测证据**：已交付成片（1920×1080@30fps）40~52s 区间，逐帧位移呈 `-0.43 / -0.000 / -0.000 / +0.000 / -0.45 …` 阶梯，运动段 **37% 的帧与前一帧像素完全相同**（停顿帧），非零帧差异 CV=1.56；隔离实验证明**纯 zoom 项同样 41% 停顿帧**（量化来自 zoompan 内部对 crop 宽高与原点的整数化），**任何参数调优都无法根治**。
  - **修复后同参数实测**：运动段停顿帧 **37% → 0**，逐帧位移 `+0.103 +0.100 +0.101 +0.104 …`（max/min=1.1），mad max/min 由 419 → **1.27**，锐度持平或更好，**总时长逐帧不变**。
  - 滤镜形态：`perspective=x0..y3:<浮点表达式>:sense=source:interpolation=cubic:eval=frame`（`eval=frame` 逐帧求值、`interpolation=cubic` 三次插值）。
- **转场 offset 必须落在整数帧边界**：xfade 的 `offset` 用「累计整数帧数 − 转场帧数」再除以 fps 计算，**严禁用 ffprobe 浮点秒时长累加**（秒级浮点误差在多次转场累积 → 混合起点落在帧中间 → 每次转场画面抖一下）。
- **段时长用 `-frames:v` 精确锁帧**（替代 `-t` 浮点秒）：段实际帧数 = `round(d*fps)` 整数，避免运动层与编码帧数差 1 导致的段尾状态不连续。
- **相邻段运动连续（三角波衔接）**：zoom 做「1.0→Z / Z→1.0」奇偶交替、平移因子做「0→1 / 1→0」同向回收，**上一段尾的裁剪窗 == 下一段头的裁剪窗**，杜绝衔接处缩放/平移跳变。方向表按 `(i//2)%4` 轮转（四方向轮换）。
- **平移量用「缩放可用空间」的比例表达，保证永不越界**：`平移 = PAN_FRAC × 可用空间/2`，其中可用空间 `Ux(z)=W(1-1/z)`、`Uy(z)=H(1-1/z)`，`PAN_FRAC ≤ 1` ⇒ 裁剪窗恒在画面内。**禁止再用固定像素值平移**（旧实现 pan 40/90/150 px 在纵轴上超出可用空间，被 zoompan 静默夹住 → 运动截断；换成 perspective 后会变成边缘涂抹）。
- **运动在 80% 时长内完成、尾 20% 静止**：xfade 重叠期两段皆静止，只做透明度交叉 → 不扭不抖；段过短（≤转场帧数+1）时压缩运动幅度，避免转场占满整段。
- **渲染前必过统一质量总门禁**：`compose_motion.py` 合成前自动调用 `scripts/video_quality_gate.py` 一次性校验三类问题——①画面抖（**运动段逐帧裁剪窗唯一：任何相邻两帧裁剪窗相同即 FAIL** + 裁剪窗不越界 + 跨段连续 + offset 整数帧，复用 `motion_quality_check`）、②编码画质契约（见 §3.8）、③素材合规（源帧须 1920×1080、**全帧同尺寸**、非空、数量对齐），FAIL 直接终止；也可单独 `python3 scripts/video_quality_gate.py <frames_dir> <durations.json> --json` 检视全量问题（退出码 0=PASS / 1=FAIL / 2=WARN-only，`--strict` 时 WARN 升格为 FAIL）。门禁脚本的契约参数（zoom_max / pan_frac / XD / 方向表 / smoothstep 公式）须与 compose_motion.py 及本 §3.6/§3.7 随时同步，否则门禁失效。
- **合成后兜底复核（强制内置于 compose_motion.py）**：成片产出后自动抽检 ≤8 段的运动段中部，逐帧差异 `max/min > 8` 即判定为「数帧静止 + 突然跳变」的运动量化阶梯并**终止**（退出码 1），提示确认未被改回 zoompan；纯长页慢速运动窗口无从判定时跳过，不误判。

### 3.8 统一质量总门禁（video_quality_gate.py，消除"渲染完才发现脏/抖/虚"）
- **为什么需要**：前面 §3.6/§3.7 的修复都是"编码参数 / 运动逻辑"，一旦有人改坏（把 `qp 0` 删了、把运动滤镜改回 `zoompan`、把 `scale=8000` 加回来、把 SwiftShader 去掉、源帧导出成 1280×720 或尺寸混用），缺陷会一直带进成片。总门禁在**跑 ffmpeg 之前**一次性把"抖动 / 编码契约 / 素材"三类全查完，FAIL 直接拦下。
- **三类检查项**：
  - **[MOTION] 画面抖**：复用 `motion_quality_check`（唯一权威实现），纯 Python 复算 perspective 逐帧裁剪窗，校验 **①运动段零位移帧（相邻两帧裁剪窗完全相同 = 量化停顿指纹，FAIL）②裁剪窗越界（FAIL）③跨段裁剪窗连续（FAIL）④xfade offset 整数帧（FAIL）⑤段极短（FAIL/WARN）⑥逐帧位移幅度体检（过慢/过快 WARN）**。
  - **[ENCODE] 编码契约**：`compose_motion.py` 必须含 `qp 0`（无损暂存）+ 单次 `crf 18` + **`perspective=` 且同时含 `interpolation=cubic` 与 `eval=frame`（亚像素运动三要素，缺一 FAIL）**、**滤镜串不得出现 `zoompan=`（防回归到整数裁剪 → 画面抖，FAIL）**、不得含 `scale=8000`；`render_animated.js` 必须含 `swiftshader`（SwiftShader 启用）、不得含 `disable-software-rasterizer`、截屏须用累计时间戳（`Date.now` + `frameInterval`）。任一违约 → FAIL（防回归）。
  - **[ASSET] 素材合规**：源帧须为 1920×1080 PNG、非空（非 0 字节）、**全帧同尺寸（混尺寸 → 裁剪窗按首帧画布算，其余帧被拉伸/裁切，FAIL）**、帧数与 `durations.json` 对齐、编号自然序连续（缺号仅 WARN）。尺寸不符既定 16:9 规格 → FAIL。
- **调用方式**：
  - 自动化任务：已内置进 `compose_motion.py` 合成前自动调用，无需人工记着跑。
  - 人工 / CI：`python3 scripts/video_quality_gate.py <frames_dir> <durations.json> [--fps 30] [--preset 1] [--scripts-dir <dir>] [--strict] [--json]`
  - 只看运动：`python3 scripts/motion_quality_check.py <frames_dir> <durations.json> [--preset 1] [--json]`
- **契约同步约束**：ENCODE 组检查的是"源码字符串特征"（且已剔除文档字符串/注释，不会把"文档里解释 zoompan 的历史"误判为仍在用），故 `compose_motion.py` / `render_animated.js` 的上述关键字一旦变更，须同步更新本 §3.8 的检查项描述，否则门禁会误判或漏判。

### 3.9 运动漂移 vs 安全区（静态帧扫描的盲区）

- **盲区在哪**：既有验证手段（SKILL.md 交付硬门槛「字幕带与内容互不侵入」的 PIL 管线）扫的是 **静态页帧** `build/frames/page_*.png`。它只能证明"排版时"内容没落进安全区，**证明不了"运动后"**——`compose_motion.py` 的 perspective 推拉会把画面内容整体位移，位移量可达约 ±40px（实测 2026-09-11）。
- **位移量推导（preset2：zoom_max=1.10、pan_frac=0.85）**：`z = 1+(zoom_max-1)s`，可用空间 `uy(z)=H(1-1/z)`，`y0 = uy·(0.5+0.5·dy·pan_frac·f)`，输出 `y_out = (y_src − y0)·z`。
  - 内容**上漂**最狠：`z=1.10` 时 `uy=98.2`，`y0max=98.2×0.925=90.8` → `y_out=(y_src−90.8)×1.1`
  - 内容**下漂**最狠：`y0min=98.2×0.075=7.4` → `y_out=(y_src−7.4)×1.1`
- **抗漂移的安全排版带（由此反解，内容本体应全部落在此带内）**：

  | preset | zoom_max | 内容带 `y_src` | 带高 | 内容左缘 `x_src` |
  |---|---|---|---|---|
  | 1 | 1.06 | `[222, 856]` | 634px | ≥ 324px |
  | 2 | 1.10 | `[238, 842]` | 604px | ≥ 357px |
  | 3 | 1.16 | `[264, 812]` | 548px | ≥ 408px |

  （`x_src` 门槛按"避开左上角水印框 x≤215"反解，比"避开整条 25% 宽安全区"宽松；若要连整条 x<480 都不进，则 preset2 需 `x_src ≥ 598`，实际排版不必那么苛刻。）
- **复核手段（补盲区，建议在合成后跑）**：`scan_motion.py` 按固定间隔从 body 抽样，只抽两块区域做像素判定——①水印列区 `x<430, y<162` 中亮度>190 的像素是否落在水印文字框外；②字幕带 `y∈[918,1000]` 是否出现亮度>135 的内容像素（body 尚未烧字幕时该带应为纯暗背景）。
- **2026-09-11 实测参照（《软件设计的哲学（中）》50 页 / 2226s）**：静态帧扫描 PASS；运动抽样 1101 帧中，水印列区"框外亮像素"227 帧、字幕带内容侵入 45 帧。**逐行剖面判定为良性**：侵入像素仅 2~7 像素/行（高亮卡片描边）或单条 1px 横线（卡片底边），内容文字最高只到 `y=930`，而字幕**文字**最低起点为 `y=931` —— 二者不重叠，水印框（`y≤68`）与内容顶缘（实测 `y≥133`）留白 ≥65px。结论：**该片未出现"字幕压字/水印压字"，可通过**；但安全区余量已被运动吃掉，属"擦边通过"。
- **给下一次的默认值**：长篇（读书营）幻灯片的 `.slide-head` 与内容容器按 `y ∈ [240, 840]`、左缘 `x ≥ 360` 排版，可直接吃掉 preset2 的漂移，避免每期都要复核。

## 4. 音频工匠（声音是半条命）

> 画面再好，音频刺耳 / 忽大忽小 / 有噪音，观众 3 秒划走。音频质量 = 响度归一 + 无爆音 + 无底噪 + 音质达标 + 节奏设计。

### 4.1 响度归一
- 整片响度**统一**（目标约 **-14 LUFS**，短视频可略高到 -13~-12 LUFS），**不忽大忽小**；配音分段拼接处听感平滑，无音量突变。

### 4.2 无爆音 / 削波
- 峰值**不超 0 dBFS**，无 clipping 破音；抽听确认无「噗」「滋」等爆音；必要时压限（limiter）再导出。

### 4.3 无底噪 / 降噪
- 无电流声、无环境噪音、无「沙沙」底噪；背景音乐（如用）与人声分层清晰。

### 4.4 音质达标
- 音频码率 **≥128 kbps（AAC）**，无压缩劣化、无金属感；采样率 ≥44100Hz。

### 4.5 节奏设计（停顿 / 重音 / 发音 / 语速）
- **停顿**：口播稿用标点 / 换行暗示停顿；关键结论前留 0.5s 停顿制造期待。
- **重音**：需强调的词（数字 / 结论 / 反常识）在稿内加粗或标注重音。
- **发音**：多音字、英文缩写、专有名词读音正确（edge-tts 多音字避坑见 SKILL.md `gen_sync_subs.py`——代理同音字法）；术语首次出现读全称。
- **语速**：整片稳定、不忽快忽慢；数字 / 金额按「念得顺口」书写（「百分之九十」优于「90%」）。

### 4.6 BGM（如使用）
- 背景音乐音量**明显低于人声**（约 -20 dB 相对人声），不抢话、不压字；风格与主题匹配；无人声干扰的纯音乐优先。

## 5. 字幕工匠（读者靠它跟上你）

> 字幕是「声音→视觉」的桥，也是完播率的隐性推手。字幕质量 = 逐字一致 + 时间同步 + 时长适中 + 断句合理 + 可读 + 分级 + 不挡内容。

### 5.1 逐字一致 + 时间同步（基础，已有四方同频兜底）
- 字幕 = 配音真实朗读（逐字），时间轴来自真实音频时间（禁止估算），`check_sync.py` exit 0 才交付。

### 5.2 时长适中
- 每条字幕停留 **0.5~3 秒**，**不闪切**（太短看不清）、**不滞留**（太长挡画面、跟不上）。

### 5.3 断句合理
- 按**语义断句**，单行 **≤32 字**，**不割裂词义**（不把一个术语/数字拆两行）；长句按意群拆。

### 5.4 可读性
- 字号够大、字体清晰、**对比度足够**（白字 + 阴影/描边，深底浅字或浅底深字）；单行完整显示，无折行、无溢出截断。

### 5.5 重点分级
- 普通句常规白字；**数据 / 结论 / 核心术语**用品牌色 + 加粗（甚至放大 120%），与普通字幕明显区分。

### 5.6 不挡内容
- 字幕落位固定底部字幕带（y≈88%~95%），**不侵入左上角水印区、不压画面主体**；内容排版已为字幕带预留留白（见 SKILL.md 第 5、15 条）。

## 6. 品控工匠（发布前逐帧走查）

### 6.1 逐帧走查清单
- 成片合成后，**按 1 秒间隔抽帧通看**，逐项检查：
  - 字幕是否挡字 / 半截 / 折行 / 溢出 / 闪切；
  - 动画是否卡顿 / 闪烁 / 中途结束 / 节奏错位；
  - 是否有半截文字、残留色块、空白页；
  - 水印是否清晰、位置固定、无压字；
  - 音频是否清晰、无爆音 / 音量突变 / 底噪 / 口误。

### 6.2 三处精听
- **开头 3 秒 / 中段 / 结尾**各精听一遍：核对字幕逐字一致、配音清晰、响度平滑、节奏自然。

### 6.3 瑕疵零容忍
- 发现**任何一处瑕疵（哪怕 1 帧 / 1 个爆音 / 1 处字幕错位）**→ 回炉修复、重新合成，**不带瑕疵交付**；「几乎没问题」≠「没问题」。

### 6.4 迭代沉淀（工匠的复利）
- 作者每一条反馈 → **根因分析**（不是「改了就行」，要搞清楚为什么会出现）→ **固化为可复用规则**（沉淀到本规范或对应 reference），同类问题永不二犯。

## 7. 持续进步机制（技能自我进化）

> 工匠不是一次做对，是**每次都比上次更好**。本技能把「不断学习、不断进步」机制化，让质量**滚雪球式**提升，而不是靠每次临场发挥。

### 7.1 产出后即时复盘（每条必做）
- 每条视频交付后，在产出日志记三行：**①这次哪里做得好（下次保留）②哪里踩了坑（根因）③下次怎么改（动作）**。

### 7.2 反馈 → 规则（强制闭环）
- 作者反馈 / 数据表现异常 → **根因分析 → 固化为规则**（写入 SKILL.md 固定规范 / 对应 reference），**当轮就改、永不再犯**。不允许「这次改了、下次忘了」。

### 7.3 数据反哺进化（每 10 期小结）
- 结合 `metrics.csv`（完播率 / 点赞 / 涨粉 / 爆款标记），提炼**「什么有效、什么无效」**：
  - 高完播 → 钩子类型 / 结构 / 时长 / 动画 / 音频手法，**提炼并推广**；
  - 低完播 / 掉速 → **定位是内容、音频、动画还是字幕的问题**，针对性改进。
- 小结结论**回写进规范本身**（更新本文档 / 对应 reference），让技能跟着数据一起进化。

### 7.4 主动学习（拆解头部账号）
- 定期拆解同赛道头部账号的爆款：钩子、结构、动画手法、音频处理、字幕样式——**吸收可复用的手艺**，融进本规范（结合 `cn-last30days` / WebSearch 竞品爆款拆解）。

### 7.5 技能版本意识
- **本技能是活文档，不是一次写死的**：每次进化都要落回 SKILL.md / references，并推 GitHub 版本留痕。禁止「经验只留在某次对话里」——不沉淀 = 白踩坑。
