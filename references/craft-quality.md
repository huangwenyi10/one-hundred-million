# 工匠级品控规范（Craftsmanship Quality）

> 目标：把短视频从「能看、能发布」提升到「**工匠级成品**」——每一句、每一帧、每一个数字都经得起放大镜审视，作者看完挑不出「这里能不能再改改」。
>
> 定位：本文档是**既有规范的进阶增量，不是替代**。基础质量门禁照旧——讲透闭环（`content-formats.md`）、四方同频（SKILL.md 第 11 条 + `check_sync.py`）、专业视觉版式（`visual-design.md`）、去 AI 味（`script-writing-guide.md`）、事实正确（SKILL.md 第 7 条）。本文档只讲**在这些「及格线」之上，怎么做到「优秀」**。

---

## 0. 工匠精神总纲

- **精益求精 = 拒绝「能用就行」，追求「挑不出毛病」**。任何一处「差不多」都是瑕疵，回炉修到零瑕疵才交付。
- **三个自问**（每次交付前问自己）：
  1. 这个数字 / 案例，读者信吗？**有名有姓、有出处吗？**
  2. 这一帧，**放大看**有没有瑕疵（1px 错位、半截文字、水印压字、动画卡顿）？
  3. 这一句，能不能**更顺、更准、更打动人**？
- **工匠标准**：读者看完能**复述**出一个核心收获（一个结论 / 一个数字 / 一个反常识），而不是「讲了一堆名词，啥也没记住」。

---

## 1. 内容工匠（把话讲到读者心里）

### 1.1 颗粒度——案例/数据「有名有姓」
- 真实公司名 / 产品名 / 版本号 / 具体数字直接写出（如「Doris 3.0 读写分离，成本降 90%」），**禁止「某大厂」「提升了 N 倍」「某头部公司」式模糊表述**。
- 数据拿不到精确值时**明确留白**（「官方未公开」），不编一个「看起来合理」的约数。

### 1.2 机制解释——每个结论讲「为什么」
- 不是「它更快」，而是「因为做了 X，所以快了 Y」——读者要的是**可迁移的因果链**，不是结论堆砌。
- 讲透闭环（是什么→为什么→怎么做→数据/案例）里的「为什么」这一环，工匠级要求**落到机制层**，不是一句「因为优化了」。

### 1.3 类比质量——把抽象讲成「秒懂的画面」
- 抽象概念必须配一个**读者熟悉的类比**（生活场景 / 日常工作），且类比**准确**——不偷换概念、不误导。
- **一个类比用到底**，中途不换比喻；类比之后**立刻回扣**到技术真实含义（「类比只是为了好懂，真实机制是……」），避免读者把类比当真。

### 1.4 记忆点——每条留一个「可复述」的钩子
- 每条视频至少留 **1 个读者看完能复述给别人听的记忆点**：一个金句 / 一个反常识数字 / 一个精炼结论。
- 这个记忆点要**在前 3 秒埋下、结尾呼应**，形成闭环记忆。

---

## 2. 视觉工匠（每一帧都耐看）

### 2.1 视觉焦点唯一
- 一屏**只有一个视觉焦点**（最大、最亮、最突出），其余元素弱化衬托；读者视线 **1 秒内**找到重点。
- 焦点不唯一 = 画面没有主次 = 失败，拆屏或弱化。

### 2.2 层级对比
- 标题 / 结论字号 **≥ 正文 2 倍**；关键数据放大到「无法忽略」（大数字 / Stat 页）。
- 颜色、字号、粗细三重手段拉开层级，禁止「全屏一样大、一样粗」。

### 2.3 留白呼吸感
- 画面留白 **≥ 20%**，不塞满；信息偏多就**拆屏**（一屏一个焦点），不压缩到密不透风。

### 2.4 配色克制
- 全片主色 **≤ 3 种**（训练营高亮色 + 中性色 + 白），强调色**只在「结论 / 数据」处**出现，不滥用高亮。

### 2.5 对齐精确
- 卡片 / 图标 / 文字边缘**像素级对齐**（同行等高、等间距、边缘对齐），无 1px 错位感；圆角、描边、阴影风格全片统一。

---

## 3. 声音与节奏工匠

### 3.1 停顿设计
- 口播稿用标点 / 换行**暗示停顿**；关键结论前留 **0.5s 停顿**制造期待（分段 TTS 时通过分段边界自然实现）。

### 3.2 重音标注
- 需要强调的词（数字 / 结论 / 反常识）在稿内**加粗或标注重音**，配音时落在重点上。

### 3.3 发音正确
- 多音字、英文缩写、专有名词读音正确（edge-tts 多音字避坑见 SKILL.md `gen_sync_subs.py` 说明——代理同音字法）；中文术语首次出现读全称。

### 3.4 语速均匀
- 整片语速稳定、不忽快忽慢（edge-tts 天然稳定；真人配音需控制）；数字 / 金额按「念得顺口」原则书写（「百分之九十」优于「90%」）。

## 4. 品控工匠（发布前逐帧走查）

### 4.1 逐帧走查清单
- 成片合成后，**按 1 秒间隔抽帧通看**，逐项检查：
  - 字幕是否挡字 / 半截 / 折行 / 溢出；
  - 动画是否卡顿 / 闪烁 / 中途结束；
  - 是否有半截文字、残留色块、空白页；
  - 水印是否清晰、位置固定、无压字；
  - 配音是否清晰、无爆音 / 停顿异常 / 口误。

### 4.2 三处精听
- **开头 3 秒 / 中段 / 结尾**各精听一遍：核对字幕逐字一致、配音清晰、节奏自然。

### 4.3 瑕疵零容忍
- 发现**任何一处瑕疵（哪怕 1 帧）**→ 回炉修复、重新合成，**不带瑕疵交付**；「几乎没问题」≠「没问题」。

### 4.4 迭代沉淀（工匠的复利）
- 作者每一条反馈 → **根因分析**（不是「改了就行」，要搞清楚为什么会出现）→ **固化为可复用规则**（沉淀到本规范或对应 reference），同类问题永不二犯。

---

## 5. 工匠自检清单（Step 7 交付前逐项过）

- [ ] 案例 / 数据**有名有姓、有出处**，无「某大厂」「N 倍」式模糊表述。
- [ ] 每个结论有**「为什么」的机制解释**，不是结论堆砌。
- [ ] 抽象概念有**准确类比**且回扣技术真实含义，一个类比用到底。
- [ ] 有 **1 个读者可复述的记忆点**，前 3 秒埋下、结尾呼应。
- [ ] 每屏**视觉焦点唯一**、字号层级 ≥2:1、留白 ≥20%、主色 ≤3 种。
- [ ] 卡片 / 图标**像素级对齐**，风格全片统一。
- [ ] 停顿 / 重音设计到位、发音正确、语速均匀。
- [ ] **逐帧走查通过**，零瑕疵交付（无挡字 / 卡顿 / 半截 / 爆音）。
- [ ] 作者反馈已**根因分析 + 沉淀为规则**，非「改了就行」。
